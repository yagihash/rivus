# 173: Go: map のキーと、チャネルで渡したポインタ経由の書き込みが、元の値から読むときに見つからない

- 状態: **open**
- 種類: サイレントな見逃し
- 言語: Go
- ROADMAP の節: -
- 守るもの: -

## 何が起きるか

- `for k := range m`(`m` は `map[*T]V`)で取ったキー `k` の指す先への書き込みが、`m` のキーを作ったときのポインタから読むと見つからない。
- チャネルへ送ったポインタを `q := <-ch`(`q, ok := <-ch` も同じ)で受け取り、`q.f = 汚れた値` と書いても、送った側の `p.f` から読むと見つからない。

結果が 1 つの形でも見つからないので、結果が 2 つ以上の命令の扱いを広げた変更(`computeLocs`)の前からある欠け。

## 原因

キーは `index_store` が `[k]` に値(内容)だけを入れ、ポインタが指す先の位置を持たない。チャネル送信(`chan.send`)も、`<chan>[]` に内容を入れるだけで、ポインタの指す先の別名を持たない。受け取る側の `computeLocs` は受け取った値を `<chan>[]*` の別名にするが、送る側がその位置に指す先を置いていないので、書き込みが元のポインタに届かない。

## 案

- キーと、チャネルで送る値がポインタのとき、`store` が、指す先の位置(`s.locs(値)` の `*` の先)を、`[k]*` と `[]*` の別名として覚える。
- 範囲は map のキーとチャネルに限り、zoo にセルを足して確かめる。
