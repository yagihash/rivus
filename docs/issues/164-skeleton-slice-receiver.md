# 164: 骨組みの生成器が、スライスやマップのレシーバのメソッドの流れを再現できない

- 状態: **open**
- 種類: 道具(モデル作成の骨組みの生成。生成器の制限)
- 言語: Go
- 見つけた経緯: `make model ... ARGS="-gen-skeleton"`(`docs/DESIGN-package-models.md` 6.11 の段階 2)で `gin` の骨組みを作り直したとき。

## 問題

骨組みの生成器は、レシーバから結果への流れの行(`gin.Context.Query` など)を、レシーバの構造体に足した非公開のフィールド `v`(マーカー)を返す本体にして再現する。レシーバがスライスやマップの型(`gin.Params`)のメソッドは、フィールドを足せないので、流れを再現できず、ゼロ値を返す本体になる。

この型のメソッドをセルで呼ぶと、実行の確認(`zoo/mark` の記録)では、マーカーが届かないので、真の注釈が成り立たない(届くはずの流れが、届かなかったことになる)。今のセル(`gin` の `query`、`bind`)は、この型を呼ばないので、zoo の結果は変わらない。

生成器は、再現できなかった行を、実行のたびに警告で出す(失敗にはしない): `warning: (github.com/gin-gonic/gin.Params).Get: the flow from the receiver is not reproduced ...`。同じ形で、危険な位置に記録できる型の引数がなく、何も記録しない sink の行も、警告に出る。

## 案

- スライスやマップのレシーバは、そのパッケージの `zooV`(ケースのマーカー)を返す本体にする(`call_result` の source と同じ)。クライアントごとのマーカーの違いは、失われる。
- または、手で書いたファイル(`skel/zoo_extra.go`)で、その型のメソッドの本体を足せるようにする(生成するメソッドを、名前で除く)。

## 確認すること

- 案の 1 つめで、`gin.Params.Get` を呼ぶセルが、実行と注釈で一致すること。
- 警告が出る行が、本当に、セルで呼ばれていないこと(呼ばれていたら、マークの固定と実行の確認が先に落ちる)。
