## G-9: `--avoid-call` が、指定と違う呼び出し点を切っても `filters` に出ない(実行で確認)
- 場所: `internal/graphq/filter.go` の `prepare`(`c.Filters = append(c.Filters, fmt.Sprintf("avoid-call %s: …", s))`)
- 位置の解決は、その桁から始まる呼び出しがなければ、同じ行の、それより前に始まる最後の呼び出し点に寄せる。`--avoid-call internal/frontend/goir/goir.go:407:18`(そこから始まる呼び出しはない)は `407:15` の呼び出しを切るが、`filters` には与えた `407:18` がそのまま出て、実際に切った呼び出し点が出ない。`a(b(c))` のような行では、意図と違う呼び出しを切りうる
- 再現: 1 行に呼び出しが 2 つある関数で、2 つ目の呼び出しの途中の桁を指定する
- 方向: `filters` に、解決した位置と `callee`、候補の数を書く。寄せたときは、寄せたと書く

## G-10: 同じ位置に呼び出し点が複数あるとき、`--avoid-call` は 1 つしか切らない(コード読解。Rust での実行は未確認)
- 場所: `avoidCall[tg.Call.ID] = true`
- DESIGN は「同じ関数の同じ位置に呼び出し点が複数あるとき(Rust の `?` の脱糖など)は、1 つの呼び出し点として扱う」と決めているが、`--avoid-call` は `tg.Call` の 1 行だけを切る。同じ位置の別の呼び出し点を通る経路が残り、切る手段がない
- 方向: 同じ関数・同じ位置の呼び出し点を全部切る。`filters` に切った数を書く

## G-11: 位置のない呼び出し点(`file:0:0`)が経路に出る(実行で確認)
- rivus 自身の索引で、`vta.go:0:0` の、関数値の呼び出しのステップが出る。位置のないステップは `--avoid-call` で指定できず、読み手はどの呼び出しか分からない
- 方向: 位置がないときは `at` を出さず、`at_unknown: true` と、分かること(呼び先の名前)を出す。呼び出し点の ID を受ける指定を足すか、「切れない」とヒントで示す

## G-12: `culprits` が空のときのヒントが「1 つ外せば届く」と読める(コード読解)
- 場所: `internal/graphq/path.go` の `withoutFilters` とヒントの文面
- フィルタが 2 つ以上あり、どれか 1 つを外しても届かない(2 つ以上がそれぞれ塞いでいる)とき `culprits` は空になるが、ヒントは「one of them cuts it; take one off」のまま
- 方向: `culprits` が空のときは、「1 つ外すだけでは届かない。2 つ以上が塞いでいる」と報告する。フィクスチャ: 2 つの `--avoid` が、それぞれ別の経路を塞ぐ形

## G-13: 依存のファイルの位置が絶対パスで、出力に利用者のホームが出る(実行で確認。出力の形が変わるので、ユーザーに伝えてから)
- `<home>/go/pkg/mod/golang.org/x/tools@v0.52.0/…` のような絶対パスが、`at` と `defined_at` に出る。rivus の出力は LLM に渡す証拠で、issue やレビューにも貼られる。利用者のホームのパスが入り、同じソースでもマシンごとに出力が変わる
- 方向: モジュールキャッシュと GOROOT の下は `<module>@<version>/<path>` の形にする。`graph` だけでなく `analyze` / `sites` / SARIF の出力も同じか、先に確かめる
