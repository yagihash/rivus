# #207 Dart: 候補 0 件の関数値の呼び出しに、型が合う関数値を補う案(今は入れない)

- 状態: **deferred**
- 種類: 道具・ベンチ(グラフのエッジ)
- 言語: Dart
- ROADMAP の節: 1
- 守るもの: -
- 題: Dart の候補 0 件の関数値の呼び出しに、型が合う関数値を補う案(今は入れない)

## 案

Dart の候補 0 件の関数値の呼び出し(#99)に、型が合う関数値を候補として補う。型が合う関数値とは、その呼び出しの関数の型に代入できる、値として使われた関数とクロージャ。エンジンを実行しないので安い。過大近似になるので、「型だけで補った」と uncertainty に書く。外部の設計者の助言。

## 数え上げの結果

zoo-dart の `no_edge` 76 件(36 の呼び出し点)を、analyzer の `isAssignableTo` で数えた。

- 候補が 32 以下で効くのは 4 行(約 5%)だけ。72 行は候補が 32 を超え(`void Function()` 527 のうち、`zooCase` への登録が 485 など)、rivus は追わない(`candidate_limit`、#77)。
- 本物の呼び出し先を含む割合は 76/76。足される偽の候補は、0 件の点の 70 行で中央値 53、最大 526。zoo は同じ形のセルが 400 以上並ぶので、実際のコードより大きく出る見込み。
- dart-gcp: 0 件の点 83 のうち、32 超が 37、型が使えない 36(型変数を含む形が 32)、2〜32 が 8 点。
- dart-curated: 0 件の点 17 のうち、32 超が 13。

## 今の Dart の extractor

型で補う形は無い。`candidates()` はメソッド呼び出しの階層(CHA)で引く。関数値の呼び出しは `callee: {kind: value}` で候補なしで出て、`typeId` が関数の型を `Function` に潰すので、IR に呼び出しの型が無い。足すなら extractor の変更が要る。候補は `valuecalls` の `resolve` が値の流れから付け、32 超で `candidate_limit`。型変数を実引数に置き換える処理が無いと、dart-gcp の 4 割は数えられない。

## 結論

効きが小さく(zoo で約 5%)、IR の型情報の追加と型変数の処理が要るので、今は入れない(ユーザーの決定、2026-11-24)。上限(32)を上げると、1 呼び出しにつき偽が数十から数百増える。効くのは、型が具体的で関数値が少ない呼び出しに限られる見込み(dart-gcp で 8 点)。

ただし、ユーザーは「効果が薄いものをひとつずつ組み合わせるとかも、もしかしたら必要になるのかな」と言っている。組み合わせの候補としては残す。`dart_services` の収束の課題(#126、#203)から、この課題を参照する。
