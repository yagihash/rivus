# 169: ガード(検査の関数)を、ルールで宣言できない

- 状態: **open**
- 種類: 書式の不足(重さ: 中)
- 言語: 全
- ROADMAP の節: 4
- 守るもの: -

Go の実際のプロジェクトでの利用(2026-11-23)から出た要望。値を検査してから使う形(検査が通らなければ止まる関数)を、利用者のルールで宣言する書式がない。sanitizer は値を変える関数のためで、「通らなければ先に進まない」検査は、同じ形では書けない。

直す方向: ガードの宣言の書式を設計する(案の段階。ADR が要る)。誤って流れを止めると、サイレントな見逃しになるので、止める範囲を狭く決める。

## 方向(2026-11-23 に決めた)

宣言の書式(上)とは別に、解析の側が、検査を見つけて、finding に見せる。

- **形:** 汚染した値を引数に取る呼び出しの結果(bool か error)で分岐し、一方の腕が、sink より前で抜ける形。
- **決め方:** 名前ではなく、構造で決める。
- **出し方:** finding を消さない。どの検査の関数を、どの分岐で通ったかを、finding に注記する。
- **範囲:** まず、1 つの関数の中だけ。#179 と、文字ごとの流れ(#185)のあとに始める。
- **合格の線の条件:** この仕組みができたら、合格の線の「修正のあと」の条件を、次の形にする。修正の前 = finding が出て、検査の注記がない。修正のあと = finding が出ないか、出るなら、修正で足した検査の関数を指す注記が付いている。それまで、修正のあとの finding の有無(`quiet_after_fix`)は、記録だけにする。説明は `bench/passline-baseline.md`。
