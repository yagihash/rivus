# 169: 検査の関数(ガード)を、ルールで宣言できない

- 状態: **open**
- 種類: 書式の不足(重さ: 中)
- 言語: 全
- ROADMAP の節: 4
- 守るもの: -

Go の実際のプロジェクトでの利用(2026-11-23)から出た要望。値を検査してから使う形(検査が通らなければ止まる関数)を、利用者のルールで宣言する書式がない。サニタイザは値を変える関数のためで、「通らなければ先に進まない」検査は、同じ形では書けない。

## 結論(2026-11-24。ADR-122)

(A) が本体。(B) は、狭めた形。

- **(A) 検査の関数の宣言(本体):** ルールに `guards:` を書く(symbol、検査される引数、通ったときの結果、`neutralises` は必須)。宣言した検査を通った値は、サニタイザと同じに、その種類の sink で止める。止めた記録 `suppressions` に、どのルールのファイルの、どの宣言で止めたかを出す。止めない形(結果を捨てる、片方の経路だけ、sink より後、など)は、ADR-122 の表のとおり。ルールの中身の管理は、rivus の外(ユーザーの判断)。
- **(B) 解析が見つけるほう(狭めた形):** プロジェクトの関数の本体の中に、引数への条件で失敗(`error` か `false`)を返す分岐があるときだけ、事実として注釈を付ける。「検査を通った」とは書かない。finding は消さない。構造だけで検査と決める形は、取り下げた(Go の `os.Open` のあとの `err != nil` が、全部検査に見えるため)。
- **順序:** 実装は、文字ごとの汚染(#185)のあと、検査を既定にするかの判断の前。始めるときは、否定のセルを先に、肯定のセルは memos の形を 1 つ。まだ始めない。
- **合格基準の条件:** 宣言ができたら、修正のあとのコミットを、宣言のルールつきで条件にする。説明は `bench/passline-baseline.md`。それまで `quiet_after_fix` は記録だけ。
