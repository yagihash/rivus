# #190 Dart(と Go のポインタ): 同じ深さの設定で、Dart は Go より 1 段早く粗くなる(参照の `*` が 1 段に数えられる)

- 状態: open
- 種類: 過検出(深さの数え方)
- 言語: Dart(Go のポインタ、Rust の参照も、同じ形のはず)
- ROADMAP の節: 2
- 優先度: 高(Dart が主な言語)
- 守るもの: 精度(新しい依存の既定 2、ADR-119)
- 題: 同じ深さの設定で、Dart は Go より 1 段早く粗くなる

## 何が誤って報告されるか

依存の深さの既定が 2 になった(ADR-119)。依存の構造体の 3 段目の値 C と、同じ 1 段目のノードの下の隣 X(`o.a.b.c` と `o.a.x`)を、プロジェクトが別のフィールドとして読んで sink に渡す形で、Go は深さ 2 で X を区別する(深さ 1 で初めて出る)。Dart は深さ 2 で、すでに X が出る(深さ 3 から区別する)。テスト: `cmd/rivus/depth_boundary_test.go`(Go)と `cmd/rivus/depth_boundary_dart_test.go`(Dart)。新しい既定 2 は、Dart では、Go の深さ 1 と同じ粗さ。

## 原因(コードを読んだ推測。確認が要る)

ポインタ的な値(Dart のクラスのインスタンスは、いつも参照)を読み書きするとき、パスに `*` の段を足す(`internal/taint/transfer.go` の `loadInto`、`storeNoted`)。`pathDepth` は `/` の数(`internal/taint/elem.go`)なので、`*` も 1 段に数える。Dart の `o.a.b.c` は `/a/*/b/*/c`(5 段)、`o.a.x` は `/a/*/x`(3 段)で、X と C が分かれるのは 3 段目。Go の構造体の値では `*` が入らず、`/A/B/C` と `/A/X` は 2 段目で分かれる。Go でも、フィールドがポインタ(`A *N2`)なら、同じ形になるはず(テストは、まだない)。

## 案

(a) **深さの数え方を直す**(助言者の好み): `pathDepth` と `pathTrunc` が、`*` の段を数えない。同じコードが、3 言語で、同じ深さで、同じ結果になる。代償: 深さ k で区別するパスが増える(ポインタの多い言語で要素が増える)ので、要素の数と時間を取り直す(AWS SDK 系の対象は、ポインタのフィールドが多い)。
(b) **言語ごとの依存の既定**: Dart は 3。数え方は直さない。簡単だが、同じ深さの設定が言語で別の意味のまま残る。
