- 種類: 誤った注記
- 言語: 全

- 題: アクセスパスを深さの上限で切った結果の finding に、注記が付かない

## 何が誤って報告されるか

アクセスパス(値の中のどの場所が汚染されているか)を深さの上限で切ると、切った先の部分も汚染されたものとして扱う(過大近似)。この切った結果で出た finding が、今は `no_uncertainty_on_path` になりうる。切ったことは出力に残らない。「経路に不確実性がない」という解釈が、誤った注記になる側である(PRINCIPLES 2 節の「誤った注記」)。

## 経緯

- 最初の実装(PR #302 のブランチのコミット `de98b0e`)は、経路の上の **どれか 1 つの関数** で切りがあれば、注記 `access_path_truncated` を付けた(関数単位)。
- memos では、141 件のうち 139 件に付いた。`no_uncertainty_on_path` と `requires_review` の差がほぼなくなった(件数だけ。場所は書かない)。
- そのため、#302 を入れる前に `b4108c79` で戻した。戻したコミットのメッセージは、既定の `Revert` の文面だけで、理由がない。理由はここに残す。

## 作り直しの方針

- finding の **値が本当に切ったパスを通ったとき** にだけ、注記を付ける(関数に切りがあるだけでは付けない)。
- 注記に持たせるもの: どの関数で、どの深さで、どのパス(根と、切る前の最初の数階層)か。数は上限を決めて切る。
- 関数サマリの要素は、大きくしない。

## 前提

既定の依存の深さを変える PR は、この注記を含めること。深さを変えると、切られるパスが増えるため。
