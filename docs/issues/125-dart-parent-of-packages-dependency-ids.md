# #125 Dart: 複数のパッケージの親を -C に指すと、依存が file: ID になり、解析されない(サイレント)

- 状態: **closed**
- 種類: サイレントな見逃し(直した)
- 言語: Dart
- ROADMAP の節: 1
- 守るもの: `cmd/rivus/dart_depcontext_test.go`(フィクスチャは `extractor/dart/test/monorepo`、`extractor/dart/test/versions`)

## 今の状態(2026-11-22)

直した。pubspec.yaml のない親のディレクトリを `-C` に指し、その下に Dart のパッケージが 2 つ以上あるとき、依存の関数の ID が `package:<name>/…` ではなく `file:///…/.pub-cache/…` になっていた。呼び出し先の ID(`package:`)と関数の定義の ID(`file:`)が一致せず、呼び出しグラフがつながらないので、依存の関数が読まれているのに解析されず、`summary.unread` にも標準エラーにも出なかった。パッケージ 1 つを `-C` に指すときは、問題は出なかった。

## 原因

`extractor/dart/lib/extract.dart` が、依存のファイルを、常に `collection.contexts.first` で解決していた。パッケージが複数あると、`first` は、その依存を import したパッケージのコンテキストとは限らず、その package_config.json に依存がないと、`package:` URI にならない。もう 1 つ、依存のライブラリを一度見たかの判定が URI だけだったため、2 つのパッケージが同じ依存の違うバージョンを読むと、2 つ目は、何も報告せずに読まれなかった。

## 直したこと

- 依存のファイルを、それを import したライブラリを解決したコンテキストで解決する(複数あれば、最初のもの)。プロジェクトのファイルは、自分のパッケージのコンテキストだけで解決する。
- 見たかの判定を、URI とファイルの場所の組にした。
- それでも `package:` に解決されない依存のファイルと、同じ依存を別のバージョン(別のディレクトリ)で読む 2 つ目のパッケージは、`dependency_not_linked` で始まるメッセージの `unread` として、1 パッケージにつき 1 件報告する(`summary.unread` と標準エラーの 1 行)。2 つ目のバージョンは読まない(ID が同じで、混ざるため)。

## 残っていること

- 同じ依存の違うバージョンを、バージョンごとに別に解析することは、していない(ID にバージョンがないため。報告だけ)。
- `package:` に解決されない依存を作る入力(`dependency_not_linked` の 1 つ目の経路)は、フィクスチャで作れていない。2 つ目の経路(別のバージョン)はテストで固定している。
