# 150: 差分テスト(標準ライブラリ): 本体を読む側が、解決できない呼び出しを「引数が結果に流れる」と近似し、行のない標準ライブラリの関数の呼び出しとインターフェース呼び出しに、見かけの流れが出る

- 状態: **open**
- 種類: 道具・ベンチ(差分テストの A 側の近似)
- 言語: Go
- ROADMAP の節: 後回し
- 守るもの: `bench/model-diff` の注釈
- 題: 差分テスト(標準ライブラリ): 本体を読む側が、解決できない呼び出しを「引数が結果に流れる」と近似し、見かけの流れが出る
- 見つけたもの: `bench/model-diff`(`make model-diff PKG=...`)、PR #195

`bench/model-diff` の A(本体を読む側)は、`io.WriteString` と `io.Copy` の `arg1` からエラー(`result1`)への流れを見つける。本体を読むと、エラーは書き込む側(読み出す側)のもので、渡したデータは入らない。`w.(StringWriter)` / `dst.(ReaderFrom)` / `src.(WriterTo)` のように、型表明で得たインターフェースの呼び出しが未解決(実装を絞れない)で、未解決の呼び出しの既定(引数は結果へ流れる)が使われたための、見かけの流れ。

モデルに足すと誤検出が増えるので、差分テストの注釈 `# model-diff: miss-reviewed io.Copy@arg1 body-default ... #150` で残している(`internal/model/builtin/go-stdlib.yaml`)。

本体を読む側が、型表明で得た未解決の呼び出しを、既定で近似するのをやめる(または、結果のうちエラーには流さない)と、この種類の注釈は要らなくなる。要らなくなったら、注釈は「stale note」と出る。

**対象の広げ方(2026-11-23)**: 差分テストが MISS を報告する原因は、本体を読む側が、解決できない呼び出しを「引数は結果へ流れる」とみなすことで、次の 2 つがある。
- 解決できないインターフェース呼び出し(上の `io.Copy` など。`crypto/rand.Int`、`rsa` と `ecdsa` と `ed25519` の `GenerateKey` の reader のエラー)。
- flows の行がない標準ライブラリの関数の呼び出し(本体のない `syscall` を通る `(*os.File).Write` のデータ、`os.ReadFile` を通る `tls.LoadX509KeyPair` のパスから証明書への流れ、`net/smtp.Client` の `c.cmd`)。

どちらも、本体の流れではなく、近似による見かけの流れで、モデルに足すと誤検出が増える。注記は、`# model-diff: miss-reviewed <symbol>@<位置> body-default ... #150` で残している。解決できる呼び出しを解決するか、flows の行がない関数の既定を「結果へ流さない」にすると、この種類の注記は要らなくなる。
