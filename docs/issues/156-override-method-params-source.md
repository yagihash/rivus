# 156: 利用者がオーバーライドするメソッドを、ライブラリが呼ぶ形のモデルの書式がない

- 状態: **open**
- 種類: サイレントな見逃し(書式の不足。モデルを足しても検出されない行が増える)
- 言語: 全(Dart の `dio` の `Interceptor.onRequest` で分かった。同じ形が、gRPC のインターセプタ、HTTP のミドルウェア、ORM のフックなどに多い)
- 優先: 中の上。実装は、Go と Rust の検証が通ってから
- 設計: [../DESIGN-callback-sources.md](../DESIGN-callback-sources.md)(`callback_param` の続き)

利用者が、ライブラリの型を継承または実装したクラスで、あるメソッド(`Interceptor.onRequest(options, handler)` など)をオーバーライドすると、ライブラリがそれを呼ぶ。そのメソッドの引数には、ライブラリが渡した値(リクエスト、コンテキスト)が入るが、モデルには、それを書く場所がない。必要なのは、「この型を継承または実装したクラスの、このメソッドの N 番目の引数は、この呼び出しの引数から来る(または、source)」と書く書式。

`callback_param` は、引数として渡された関数(関数リテラル、名前のある関数)の引数を source にするもので、型のメソッドのオーバーライドは対象外(呼び出しの側に関数が現れない)。`calls:` の行も、呼び返す先が型のメソッドである形は書けない。

書式が入ったら、`dio` のモデル(PR #202)の `Interceptor` の行を足し、zoo のセルを足す。
