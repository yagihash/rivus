# 既定で off の機能

結果や動作を変える機能のうち、既定で off(または、既定を変える途中)のものの一覧。フラグが増えると、結果の組み合わせが増え、どの結果をどのフラグで出したかが追えなくなる。そのため、一覧と、足す・消す規則を持つ。

- 状態は、2026-11-23 時点。フラグは `rivus analyze -h` と `-help-all` のもの。足した日は `git log -S'"<フラグ名>"' -- cmd/rivus` の最古のコミット。
- 「既定にする条件」と「消す条件」は、書いた文書がある場合だけ、その文書を示す。どこにも書かれていないものは **未決** とする(ここで先に決めない)。
- 診断と調整のフラグ(`-pass-stats`、`-cpuprofile` など)と、解析の範囲を決める指定(`-lang`、`-C`、`-categories` など)は、機能ではないので、ここに入れない。

## 計画(まだ実装されていない)

次のフラグは**まだ実装されていない。計画**。実装する PR で、上の表に 1 行を足す。

- `-char-taint`(#185。文字列から取り出した 1 文字の byte、rune、コードユニット、char にも汚染を運ぶ)。既定にする条件: (1) 見逃しのセル(zoo の `F/conv/char-*`)が、3 言語で通る、(2) 文字と定数の算術(`c - 'a' + 'A'`)を運ぶ、(3) 既定のフラグ(これを付けた形)で、合否の線を通る、(4) 増える finding のそれぞれで、原因の段に注記が付く。消す条件は未決。先に、IR の `CharRead` を extractor が付ける(Go はこの変更で付く。Dart と Rust は、それぞれの PR)。

既定で働く機能を止めるフラグは、機能の一覧に入れない: `-no-deps`、`-no-builtin-rules`、`-no-project-rules`、`-deterministic-only`、`-no-fetch`。

## 規則

- **フラグの数が増えたら、新しいフラグを足す前に、既存のものを整理する。** 整理とは、既定にする、消す、または、残す理由をこの表に書く、のどれか。この表に、足した日から長く動かない行があるときも同じ。
- 結果を変える機能は、フラグの後ろに置き、フラグが off のとき、出力が今と同一であること(テストで確認する)。
- 新しいフラグを足す PR は、この表に 1 行を足す: 足した日、既定にする条件、消す条件。条件が決まっていなければ、「未決」と書き、決める人を PR の本文に書く。
- 規模のために精度を落とす機能をフラグにするときは、[ADR-118](adr/118-scale-mechanisms-three-conditions.md) の 3 条件を、その ADR に書く。
