## 0. 安全(いつでも最優先)

- **目的**: 解析の対象(攻撃者が制御しうる)が、rivus を動かすホストに何もさせないこと。
- **今の状態**: Rust の信頼しないコードは、macOS のサンドボックス(Seatbelt)の下だけで読む(ADR-093。[rust-isolation.md](rust-isolation.md)、[DESIGN-macos-sandbox.md](DESIGN-macos-sandbox.md)。Docker の経路は消した)。Linux には隔離がなく、既定では何も実行せずに止まる(`-unsafe-host-exec` だけ)。**隔離なしでは、取得したクレートのビルドスクリプトとマクロを実行しない**(クラウドのモデル作成では、Rust を扱わない。Rust のモデルの確認は、ローカルの macOS のサンドボックスの下で行う。#148)。取得元の既定は crates.io だけ。取得のフェーズのネットワークの絞り込みは案([DESIGN-fetch-network.md](DESIGN-fetch-network.md)、#110)。Go と Dart には、隔離がまだない(PRINCIPLES 8 節)。
- **ユーザーの判断(2026-11-22)**: 取得のフェーズのネットワークの絞り込みと、Go / Dart の隔離は、しばらくやらない。帰結として、第三者のコードの実行と、新しい第三者のパッケージのまとまった解析は、引き続きしない(観測との照合は、zoo と自前の curated だけで進める)。
- **次の作業**: 後回しのハードニング(#110〜#122。取得のプロキシ、`bsd.sb` の棚卸し、メモリとプロセス数の監視、macOS の CI の全体など)、出力に target triple を出す(#146)、ワークスペースの中の crate(#147)、Linux での Rust の扱い(#148)。制御を外すフラグ(`-unsafe-host-exec` など)が出力に出ること(`summary.isolation`)は済み。`[env]` で IR が空になる件は、直らない(ADR-093)。
- **あとで隔離を足すときの最初の対象(相談役の判断、2026-11-22。着手の時期は未定)**: モデル化のタスクの、実行で確かめる手順(`DESIGN-model-authoring.md`)。第三者のソースを読むエージェントが、シェルと実行の権限を持つ、いちばん権限の大きい使い方なので。今は、信頼できるコードにだけ使う、と知らせるに留める(ユーザーの判断)。
- **ルール**: Go / Dart の隔離ができるまで、新しい第三者のパッケージをまとめて解析・実行しない。Rust の第三者のコードは、サンドボックスの中だけ(Linux では実行しない)。
- **終わりの条件**: 3 言語とも、信頼しない入力を隔離の中だけで扱える。#110〜#122、#146〜#148 を閉じる。
