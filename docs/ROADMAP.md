## 0. 安全(いつでも最優先)

- **目的**: 解析の対象(攻撃者が制御しうる)が、rivus を動かすホストに何もさせないこと。
- **今の状態**: Rust の信頼しないコードは、macOS のサンドボックス(Seatbelt)の下だけで読む(ADR-093。[rust-isolation.md](rust-isolation.md)、[DESIGN-macos-sandbox.md](DESIGN-macos-sandbox.md)。Docker の経路は消した)。Linux には隔離がなく、既定では何も実行せずに止まる(`-unsafe-host-exec` だけ)。**隔離なしでは、取得したクレートのビルドスクリプトとマクロを実行しない**(クラウドのモデル作成では、Rust を扱わない。Rust のモデルの確認は、ローカルの macOS のサンドボックスの下で行う。#148)。取得元の既定は crates.io だけ。取得の段階のネットワークの絞り込みは案([DESIGN-fetch-network.md](DESIGN-fetch-network.md)、#110)。Go と Dart には、隔離がまだない(PRINCIPLES 8 節)。
- **ユーザーの判断(2026-11-22)**: 取得の段階のネットワークの絞り込みと、Go / Dart の隔離は、しばらくやらない。帰結として、第三者のコードの実行と、新しい第三者のパッケージのまとまった解析は、引き続きしない(観測との照合は、zoo と自前の curated だけで進める)。
- **次の作業**: 後回しのハードニング(#110〜#122。取得のプロキシ、`bsd.sb` の棚卸し、メモリとプロセス数の監視、macOS の CI の全体など)、出力に target triple を出す(#146)、ワークスペースの中の crate(#147)、Linux での Rust の扱い(#148)。制御を外すフラグ(`-unsafe-host-exec` など)が出力に出ること(`summary.isolation`)は済み。`[env]` で IR が空になる件は、直らない(ADR-093)。
- **あとで隔離を足すときの最初の対象(相談役の判断、2026-11-22。着手の時期は未定)**: モデル化のタスクの、実行で確かめる段(`DESIGN-model-authoring.md`)。第三者のソースを読むエージェントが、シェルと実行の権限を持つ、いちばん権限の大きい使い方なので。今は、信頼できるコードにだけ使う、と知らせるに留める(ユーザーの判断)。
- **決まり**: Go / Dart の隔離ができるまで、新しい第三者のパッケージをまとめて解析・実行しない。Rust の第三者のコードは、サンドボックスの中だけ(Linux では実行しない)。
- **終わりの条件**: 3 言語とも、信頼しない入力を隔離の中だけで扱える。#110〜#122、#146〜#148 を閉じる。

## 3. 依存込みの解析が、実用的な時間で終わること

- **目的**: 実際のプロダクトを、`-no-deps` なしで解析して、終わること。
- **今の状態**: 本体を読むとコストが著しく大きい依存を、モデルで切る仕組みは、次のとおり。実装の多いインターフェースのメソッドを、委譲のクリーク全体のモデルで切る(ADR-098。`package:http` の `Client.send`。`dependency_body_unread` で示す)。依存の中では source と sink を探さない(ADR-099、`summary.dependency_sites`)。パッケージ単位で本体を読まない宣言(`body_replaced_packages`)は、3 言語にある(ADR-100、105、111。Rust は読み込みの時間は減らない)。**組み込みのモデルで宣言しているものは、まだない**(`go-github.yaml` にコメントがあるだけ)。差分テスト(`bench/model-diff`。本体とモデルの flows を、公開の API ごとに比べる)は、週 1 回と手動の実行だけで、**PR ではまだ動いていない。これから**(進行中の PR はない)。`make model` と `make model-diff` はある。エージェントが手順書を読んで 1 パッケージずつ作る流れは、停止した。
- **測定(前の記述から引き継いだ数字。取り直していない)**: `bench/gcp` は、既定 40.7 秒 / 4.45 GB、`-no-deps` 0.4 秒 / 64 MB、流れ 27 件は同一、確信(clear)が 19 → 15、モデルのない呼び出し先は 29 種で、finding の経路に載るのは 5 種。
- **次の作業(この順)**:
  1. 差分テストを PR で動かし、pure / sanitizer / source の行も比べる
  2. 今あるモデルに、宣言を入れる。1 パッケージずつ、既定の解析の前後の数字を付ける
  3. 依存込みのベンチと、数字の記録(`bench/LEDGER.md`)
  4. コストの高い依存から、流れのモデルを作る(型からの生成器を差分テストと組にする、段階 3。到達性で推移的な依存を落とす、段階 5。[DESIGN-package-models.md](DESIGN-package-models.md) の 7 節)
  5. エンジンの側のコスト(動的な呼び出しの候補、値の合流、要約の持ち方)の、止めてあった調査の再開
- **利用から出た要望**: #166(`-max-memory`。メモリの上限で止める)、#167(taint の段階の進捗の表示)、#174(extractor の読み込みの進捗)、#175(Dart のモノレポの `-C`)、#176(Flutter のメンバーを含む workspace)。#127(`-timeout` の超過の残り)。
- **終わりの条件**: 既定のフラグ(`-no-deps` なし、`-body-replaced` を手で書かない)で、memos(usememos/memos 26.11.2、`00fcd170281a75fc0e95ec4f2f54f43d32fe81bd`)について、`PASS memos time=<s>/180 mem=<GB>/8 converged=yes detected=yes` の 1 行が出ること。4 つの条件はすべて必要: 180 秒以内に終わる、メモリが 8 GB 以内、収束する、公開済みで修正済みの CVE-2025-65799(パストラバーサル)を、修正前のコミット `1d7efb158045924ab87f58d567bd79cd92edf6af` で検出し、修正後の `5f57f48673e2054f404b2c5b497a8eaa3690591d` では検出しない(`path_traversal` の finding の件数だけを比べる)。`make bench-passline` で出す(`bench/deps_bench.py`、対象は `bench/deps-targets.json`)。今の線は `FAIL`(2026-11-23。メモリの上限で止まる。数字は `bench/LEDGER.md`)。Dart の線は、cocoon の `app_dart`(`ae9eb1beaf765d644cc85dde38def030c80b4b7d`。cwd は `app_dart`、`-allow-deps-under <cocoon>/packages`、`dart pub get` だけ、ルートの workspace の Flutter のメンバーはコピーで外す)。条件は memos と同じ(既定のフラグ、180 秒と 8 GB 以内、収束)。今の線は `PASS cocoon time=101/180 mem=1.78/8 converged=yes detected=n/a`(2026-11-23。公開の脆弱性の助言がないので、検出は n/a)。**検出は、脆弱性の単位で数える**(memos と同じ。その脆弱性の、ラベルを付けた位置のどれか 1 つを通る finding が 1 つでもあれば `detected=yes`)。位置の単位の数は、同じ行に参考として `through_tp=<n>/<N>` で並べる(判定には入れない)。Dart の検出は、dart-lang/pub の zip slip(`bench/dart-pub`、公開の修正済みの脆弱性 1 つ、ラベル 9 か所)の的 `dart-pub` で見る。線は未決で `INFO`。既定のフラグでは、収束しないので、今は `detected=no`。dart_services は、重い依存 `package:analyzer` の負荷の対象で、`INFO` のまま(深さの実験の対象でもある)。宣言したパッケージが、全部、差分テストを通っている。

## 5. エージェントが問い合わせるインターフェース

- **目的**: AI のエージェントが、`graph` などを、最小の権限で使えること。スキルと MCP は、導入の手軽さへの投資ではなく、**最小限必要なもの**([DESIGN-agent-interface.md](DESIGN-agent-interface.md)。**案。ユーザーの考えは未確定**)。
- **順(相談役の判断、2026-11-22)**: **最小のインターフェース**(`graph` と、保存した結果への問い合わせを、読むだけの道具として出す MCP + 使い方のスキル 1 つ)→ **それを使って、「エージェントだけ」対「エージェント + rivus」の測定を 1 回**(方向の指標)→ 測定の結果を見て、作り込む所を決める。**測定の前に、インターフェースを作り込まない。**
- **着手の条件**: 2 節と 3 節の主な作業が進んでから。#91、#95 は、この前に直す。
- **終わりの条件**: 最小のインターフェースで、測定が 1 回できる。
