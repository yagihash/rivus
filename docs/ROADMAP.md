## 0. 安全(いつでも最優先)

- **目的**: 解析の対象(攻撃者が制御しうる)が、rivus を動かすホストに何もさせないこと。
- **今の状態**: Rust の信頼しないコードは、macOS のサンドボックス(Seatbelt)の下だけで読む(ADR-093。[rust-isolation.md](rust-isolation.md)、[DESIGN-macos-sandbox.md](DESIGN-macos-sandbox.md)。Docker の経路は消した)。Linux には隔離がなく、既定では何も実行せずに止まる(`-unsafe-host-exec` だけ)。**隔離なしでは、取得したクレートのビルドスクリプトとマクロを実行しない**(クラウドのモデル作成では、Rust は、モデルは書き、extractor を使う確認は CI に任せる。#148)。取得元の既定は crates.io だけ。取得の段階のネットワークの絞り込みは案([DESIGN-fetch-network.md](DESIGN-fetch-network.md)、#110)。Go と Dart には、隔離がまだない(PRINCIPLES 8 節)。
- **ユーザーの判断(2026-11-22)**: 取得の段階のネットワークの絞り込みと、Go / Dart の隔離は、しばらくやらない。帰結として、第三者のコードの実行と、新しい第三者のパッケージのまとまった解析は、引き続きしない(観測との照合は、zoo と自前の curated だけで進める)。
- **次の作業**: 後回しのハードニング(#110〜#122。取得のプロキシ、`bsd.sb` の棚卸し、メモリとプロセス数の監視、macOS の CI の全体など)、出力に target triple を出す(#146)、ワークスペースの中の crate(#147)、Linux での Rust の扱い(#148)。制御を外すフラグ(`-unsafe-host-exec` など)が出力に出ること(`summary.isolation`)は済み。`[env]` で IR が空になる件は、直らない(ADR-093)。
- **あとで隔離を足すときの最初の対象(相談役の判断、2026-11-22。着手の時期は未定)**: モデル化のタスクの、実行で確かめる段(`DESIGN-model-authoring.md`)。第三者のソースを読むエージェントが、シェルと実行の権限を持つ、いちばん権限の大きい使い方なので。今は、信頼できるコードにだけ使う、と知らせるに留める(ユーザーの判断)。
- **決まり**: Go / Dart の隔離ができるまで、新しい第三者のパッケージをまとめて解析・実行しない。Rust の第三者のコードは、サンドボックスの中だけ(Linux では実行しない)。
- **終わりの条件**: 3 言語とも、信頼しない入力を隔離の中だけで扱える。#110〜#122、#146〜#148 を閉じる。

- **課題**: #77、#81、#83、#84、#87、#92、#93、#98、#99(グラフのエッジ: #98、#99)。**関数値の第 2 歩とキャプチャセルで、#76、#78、#79、#81、#99 と #77 の残りを閉じる**(終わりの条件に入れる)。
- **止めてあるもの(関数値の候補を補う機能)**: 第 2 歩の最初のバージョンは実装済みで、`-resolve-func-values`(実験。既定 off)の後ろにある([DESIGN-callouts.md](DESIGN-callouts.md) 5.6 節)。止めてあるのは、(a) 既定を on にする判断(zoo と curated での差分の分類が先)、(b) キャプチャセル、(c) 課題 #124(補った候補がサイトの列挙に戻らない。本体のない候補で補った注記が出ない)。再開の順は、組み込みモデルと、依存込みの解析を終わらせる作業のあと(今の主な作業を優先)。
- **指標: 候補が 0 件の値の呼び出し**(2026-11-22、`internal/valuecalls` の `TestZeroCandidateCalls`。使い方はそのコメント。数えるのは、extractor も `valuecalls` も候補を付けず、上限にも達しない、関数値の呼び出し)。主な作業は「Dart の値の呼び出しの、候補 0 件を減らす」(観測との照合で出た「グラフにないエッジ」、#78、#79、#99 の根)。

  | ベンチ | 値の呼び出し | 候補 0 件 | 内訳(呼ばれる値の出所) |
  |---|---|---|---|
  | zoo-dart | 85 | 38 | 関数の戻り値 / 次の要素 18、パラメータ(フィールド・要素を通る)6、パラメータ 4、その場で作った値 8、キャプチャした変数 1、グローバル 1 |
  | dart-curated | 74 | 21 | 関数の戻り値 / 次の要素 10、キャプチャした変数 5、パラメータ 2 + 2、その場で作った値 1、グローバル 1 |

  | go-curated | 22 | 1 | パラメータ 1 |
  | zoo-rust | 3 | 3 | パラメータ 3 |

  (値は 2026-11-22 に取り直した。zoo のセルが増えたので、前の表より、値の呼び出しと候補 0 件が増えている。第 2 歩(フラグ `-resolve-func-values`)の実装のあとに、フラグ off の値と on の値を並べる。`#97` で zoo-dart の 3 か所が減った。関数の戻り値 10 のうち、自分のコードがクロージャを返す形が約 9 で、コンテナの次の要素が約 5。Dart は、Go の 5 〜 10 倍の割合で候補 0 件になっている。)
- **終わりの条件**: 正解を緩める変更が CI で止まる。観測との照合が Dart で回り、未知の欠落の候補を出す。

## 3. 外から差し込むルール

- **依存をモデルで切る(ADR-092、098、099、100)**: 目的: 本体を読むとコストが著しく大きい依存を、条件つきで、モデルで切れる。モデルは、解析のコストのためだけでなく、依存の中の sink を検出するためにも要る(依存の関数の中では source と sink を探さない。ADR-099、`summary.dependency_sites`)。今の状態(済み): 実装の多いインターフェースのメソッドを、委譲のクリーク全体のモデルで切る(ADR-098。`package:http` の `Client.send`。`dependency_body_unread` で示す)。依存の中のサイトを探さないことの明記(ADR-099)。パッケージ単位の宣言(`body_replaced_packages`、ADR-100)の解析の側。**パッケージ単位の宣言の段階([DESIGN-package-models.md](DESIGN-package-models.md) の 7 節。順は 0 → 2 → 1 → 4 → 3 → 5)**: 段階 0(モデルの PR を並べて出す準備。PR #178 など)と段階 2(宣言の書式と解析の側。PR #179)は済み。**段階 1(差分テスト `bench/model-diff`。本体とモデルの flows を、公開の API ごとに比べる)と、段階 4(extractor に宣言を渡して、読み込みの時間を減らす)は進行中**。段階 3(型からの生成器と、差分テストを組にする)と、段階 5(到達性で、推移的な依存を落とす)はこれから。次の作業: 段階 1 と 4 を終え、各段階の PR に、公開のベンチ(`bench/dart-gcp`、`bench/dart-grpc`、`bench/go-s3`)の前後の数字を付ける。測定: `bench/gcp` は、既定 40.7 秒 / 4.45 GB、`-no-deps` 0.4 秒 / 64 MB、流れ 27 件は同一、確信(clear)が 19 → 15、モデルのない呼び出し先は 29 種で、finding の経路に載るのは 5 種。終わりの条件: 差分テストで、切った状態の流れと境界のエッジが、本体を読んだ状態と同一。`bench/gcp` で clear が 19 に戻る。

- **利用からのフィードバック**(Go の実際のプロジェクトでの利用から。2026-11-23。**課題としては、まだ起票していない。相談役が番号を付ける**): (1) `-max-memory`(メモリの上限で止める)、(2) taint の段階の進捗の表示、(3) `analyze` の sink ごとの要約、(4) ガードの宣言、(5) ラベルを受ける sink がないときと、`query` の綴りの誤りの警告、(6) `graph` の答えの `complete`(#123 と同じ種類)。(1)(2)(5)(6)は、サイレントな見逃しや、利用者を止める形を減らす。起票したら、この項目に番号を並べる。

## 4. エージェントが問い合わせるインターフェース

- **目的**: AI のエージェントが、`graph` などを、最小の権限で使えること。スキルと MCP は、導入の手軽さへの投資ではなく、**最小限必要なもの**([DESIGN-agent-interface.md](DESIGN-agent-interface.md)。**案。ユーザーの考えは未確定**)。
- **順(相談役の判断、2026-11-22)**: **最小のインターフェース**(`graph` と、保存した結果への問い合わせを、読むだけの道具として出す MCP + 使い方のスキル 1 つ)→ **それを使って、「エージェントだけ」対「エージェント + rivus」の測定を 1 回**(方向の指標)→ 測定の結果を見て、作り込む所を決める。**測定の前に、インターフェースを作り込まない。** 着手は、関数値の第 2 歩と、モデル化の試行 1 回目のあと。#91、#95 は、この前に直す。
- **終わりの条件**: 最小のインターフェースで、測定が 1 回できる。
