## 7. 実装の段階と規模

**順番(相談役の判断): 0 → 2 → 1 → 4 → 3 → 5。** 0 と 2 は、別の PR で並行する。4 は、Dart の extractor が時間の 9 割なので、2 のすぐあと。**各段階の PR に、公開のベンチ(`bench/dart-gcp`、`bench/dart-grpc`、`bench/go-s3`)の前後の数字(時間、メモリ、finding の ID の集合)を付ける。** `bench/go-s3`(3.1 節の合成。約 60 行の `main.go` と `go.mod` / `go.sum`)は、ベンチとして入れる(定期の層だけ。PR の CI には入れない)。

| 順 | 段階 | 内容 | 規模(見積もり) | 何が効くか |
| --- | --- | --- | --- | --- |
| 1 | 0 | 準備: 6.1 の共有のファイルの分割、zoo-dart の `pubspec.lock` をコミットしない、`cases.dart` の生成。(6.2 のゲートは #167 で済み) | 中(1〜2 PR。スクリプトとテストの読み込み) | モデルの PR が並べて出せる |
| 2 | 2 | **(a) 宣言の書式と、解析側**(`-no-deps` のパッケージ版)。`unread_packages` をルールに足し(書いたパッケージだけに効く。配下は明示の書き方)、コアが、IR を読むとき、宣言のあるパッケージの関数を、本体のない関数として扱う。`summary` に一覧。フラグ(指定と無効化)。index の鍵。呼び返しの既定(関数の値や利用者の実装が渡されたのに `calls:` がないときは、呼ばれるものとして扱い、uncertainty) | 中(`internal/model`、`internal/sg`、`internal/taint`、`cmd/rivus`。コア側だけ。言語を問わない) | 解析の時間とメモリ(Go の S3 合成: 12 GB → 0.6〜1.6 GB、打ち切り → 数秒)。読み込みの時間は減らない |

段階 2 が、効果が大きく、リスクが小さい(コア側だけ)。Rust は、`cargo check` が全部コンパイルするので、読み込みの時間は減らない(IR の書き出しと、コアが読む量は減る)。
