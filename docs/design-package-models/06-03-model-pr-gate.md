### 6.3 モデルの PR のゲート(CI)

- 今の `ci.yml` は、`internal/**` の変更で、`code`、`dart`、`rust` の 3 つの許可の一覧に当たり、全部のジョブを実行する(`internal/model/builtin/*.yaml` も `internal/**`)。`cmd/rivus` のテストは、5 つのシャードに分かれ、その中に、zoo のテスト(`TestBuiltinRowsAreHitByTheZoo` など、行が zoo で一致するテスト)がある。**だから、行が zoo で一致するテストは、モデルの PR で、今も必ず実行される。** CI が通れば入る(auto-merge)ので、これがゲートになる。
- 差分テスト(MISS 0): **道具は実装済み**(`bench/model-diff`。手順書 9 節)。CI には、定期と手動の層に `model-diff` のジョブ(`continue-on-error`。週 1 回と `workflow_dispatch`。標準ライブラリの 6 パッケージと `package:http`)があり、**PR のジョブ `model-diff-changed` を足した(2026-11-23)**: `ci.yml` の paths-filter の `models`(`internal/model/builtin/*.yaml`)が変わった PR だけで動き、`make model-diff-changed BASE=<基準の sha>`(`-run-changed`)が、**行(flows、pure、sinks、sanitizers、sources)が基準と違うパッケージだけ**を 1 つずつ差分テストにかけ、最後に 1 つの表を出す(コメントだけの変更では 0 件)。**Go だけ**を回し、Dart と Rust の変更は表に `not run` と出す(通ったことにはしない)。MISS、注釈のない EXTRA、エラー(行のシンボルがパッケージにない、行が指定する位置が関数にない、を含む)で失敗する。未検証は失敗にしない。行ごとに「確認した / 確認していない」の数を出す(手順書 9 節)。数(2026-11-23。Go の標準ライブラリ 617 行のうち、確認していない行は 275 から 269 に減った。`.dead-allow` の Go の行 594 は、確認 330 から 353、行に誤り 31 から 9、確認していない 233 から 232)は `bench/model-ledger.md`。CI の時間は、そのパッケージの分だけ増える(測定: Go のパッケージで 0.5〜1 秒の解析と、取得と `go mod tidy`)。
- **差分テストの範囲の外(型からの生成器と、sink / source の候補の導出(課題 #144 の設計)の前提)**: モデルの行がない関数は、差分テストの範囲の外(プローブは、モデルの行にある関数だけを対象にする)。標準ライブラリの型の公開メソッドを全部並べて、行の有無を見る照合が、別に要る(例: `database/sql.Conn` の `QueryContext` の行の欠け)。
- 依存の取得(差分テストに要る): Go は `go mod download`(`actions/setup-go` のキャッシュ。バージョンは、モデルのファイルの冒頭に固定)。Dart は `dart pub get`(`~/.pub-cache` のキャッシュ。`pubspec.lock` をキーに)。Rust は `cargo fetch --locked`(`Cargo.lock` で固定)。取得先は、公開のレジストリ(proxy.golang.org、pub.dev、crates.io)だけを許可する。取得したコードは実行しない(Go は型検査まで、Dart は analyzer まで、Rust は rustdoc の JSON まで。ビルドスクリプトと proc macro が動くので、Rust は、サンドボックス(macOS)の下か、信頼できるコードだけ)。ネットワークの制限: `permissions: contents: read` のまま、取得のステップ以外はネットワークなし(ランナーの設定では絞れないので、ステップを分けて、テストのステップに取得物の実行がないことを、レビューで守る)。
- PR の範囲の確認(モデルの PR が、モデル以外を触っていないこと): ジョブが、変更されたファイルが、`internal/model/builtin/*.yaml` / `*.gen.yaml`、`bench/zoo-*/` の中の自分のパッケージのディレクトリ、`bench/zoo/marks.d/` だけであることを確認する。範囲の外(コード、ゲート、ワークフロー)を触る PR は、自動で通さない(`ci-ok` が、人のレビューを要求する)。**これは、ブランチ名 `model/*` の PR だけに適用する**(提案)。
