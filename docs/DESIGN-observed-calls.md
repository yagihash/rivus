# 観測した呼び出しとの突き合わせ(Dart から)

> - 状態: **案**。最小の試行を、動物園の Dart と、自前の `bench/dart-curated` で 1 回通した(下の 5 節)。CI には載せていない。
> - 確認: 2026-11-22、926ac45 に載せた試行(`bench/zoo-dart/observed/`)。数字は、その手順を実際に走らせたもの。
> - 関連: [DESIGN-zoo.md](DESIGN-zoo.md)(動物園は、実行で正解の裏付けを取る)、[GRAPH.md](GRAPH.md)(突き合わせる相手のグラフ)、[ROADMAP.md](ROADMAP.md) 1 節。

## 1. 何のためか

動物園は、**知っている形**の正解を守る。こちらは、**まだ知らない形**を見つける。

テストを実行して、実際に起きた呼び出し(呼び元の呼び出し点 → 呼び先の関数)を記録する。それが、rivus のグラフ(`rivus index` が作る SQLite の `callsites` と `edges`)に入っているかを比べる。**入っていない辺は、記法の取りこぼしの候補**になる。

- 向きに注意: これは「rivus が言ったことが正しいか」ではなく、「実際に起きたのに、rivus が言わなかったこと」を探す。黙った見逃しを見つける道具で、誤検出は見つけない。
- 辺が欠けても、taint の結果が変わるとは限らない(例: 返したクロージャは、作った所で「呼んだものとして」扱うので、呼び出しの辺がなくても流れは見つかる。`clos/returned`)。ただし `rivus graph` は辺だけを見るので、エージェントには欠けて見える。どちらに効くかは、辺ごとに別に見る。

## 2. 試した方法

関数の ID を rivus に合わせられるかが決め手。2 つ試した。

| | 方法 A: sink を呼んだ所の stack | 方法 B: 全部の関数の入口の stack |
|---|---|---|
| 何をするか | 動物園の harness(`exec/zoo_mark`)が、sink を呼ぶたびに `StackTrace.current` をそのまま保存する | cells の**コピー**の、全部の関数と全部のクロージャの先頭に `__rv.rvEnter()` を差し(`instrument.dart`)、入口ごとに stack の先頭 4 行を保存する |
| 元のコードへの手入れ | なし(`ZOO_STACKS=1` のときだけ記録。ふだんの出力は同じ) | コピーだけ。元は触らない |
| 見える辺 | sink に届く**呼び出しの連なり**だけ | 実行された関数の**入口すべて** |
| 見えない辺 | sink の stack に載らないもの(返したクロージャを呼ぶ所、値を返すだけの経路) | 入口の前に失敗するもの、`await` の再開のあと |

どちらも、stack の 1 行 `名前 (package:…/ファイル.dart:行:桁)` から、**呼び出し点の位置**(1 つ外側の行の位置)と**呼び先の関数**(その行の名前と位置)を取る。

試さなかったもの: VM サービスのカバレッジ(`dart test --coverage`)。行や関数が実行されたかは分かるが、**誰が誰を呼んだかは分からない**ので、辺の突き合わせにはならない(動物園の「文の網羅」の確認には、すでに使っている)。

## 3. 関数の ID の合わせ方

stack の行と、グラフの関数(`funcs.fid`、extractor の `symbolOf`)を、次のように結ぶ。

- **ライブラリ**: stack の `package:zoo_cells/clos/inline.dart` は、fid の `#` の前(`package:zoo_cells/clos/inline.dart#…`)と一致する。グラフに関数のないライブラリ(SDK、`test`、harness)は、突き合わせの外。
- **トップレベルの関数・メソッド**: stack の名前(`f3`、`PrinterDecoy.run`)が、fid の `#` の後と一致する。
- **クロージャとローカル関数**: stack は `vuln.<anonymous closure>`、`vuln1.f`。グラフは `vuln$1`(**始まりの位置**で番号が付く)。親の名前で `vuln$` から始まる fid を探し、**stack の位置より前で、いちばん近い始まり**のものを取る。同じ関数の中のクロージャが入れ子のとき、親の側の行の位置を子と取り違えうる(試行では、この取り違えで偽の欠落は出なかったが、保証はない)。
- **呼び出し点**: VM が言う桁は、名前の先頭(`f3(s)` の `f3`)。グラフの桁は、引数の `(`。そこで、**同じ行で、桁が stack 以上の最小のもの**を呼び出し点とする。方法 B は、差した文字の分だけ桁がずれるので、**同じ行の呼び出し点のどれか**が、その呼び先への辺を持てば合う、と緩める(行が同じなら「ある辺を見逃した」は言えるが、「同じ行の別の呼び出しとの取り違え」は見えなくなる)。
- 位置がずれる、名前が引けない、ときは、結果に `no_callsite`、`callee_unresolved` として**別に数える**(捨てない)。

## 4. 数えられないもの(言うべき限界)

- **SDK の中**: `List.forEach` などが、渡されたクロージャを呼ぶ辺は、グラフには「呼び出し点 → SDK の関数」と「参照(`refs`)」としてある。観測は「SDK の関数 → クロージャ」なので、**辺としては比べられない**。代わりに「そのクロージャを指す参照がグラフにあるか」を見る(`sdk ok` / `sdk no_ref`)。
- **非同期の境目**: `await` のあとの再開、`Future.then`、`Timer`、`scheduleMicrotask` で呼ばれたクロージャの stack は、`<asynchronous suspension>` で切れて、**元の呼び元が見えない**。同期の呼び出しの連なりだけが見える。
- **tear-off(`obj.method` を値として持つ)と暗黙の呼び出し**: tear-off は呼び元の位置が「呼ぶ所」で、グラフの `value` の辺か `refs` と別の形になる。`toString` の文字列補間からの呼び出し、`call` メソッド、getter も、呼び出し点の形が違い、`no_callsite` か `sdk no_ref` で出る。誤りか、辺の種類の違いかは、**1 件ずつ見て決める**。
- **実行されなかった枝**: 動物園は文の網羅が 100% になるよう作ってあるが、curated は違う。実行されなかった呼び出しは、何も言えない。
- **入口の前**: 方法 B は、関数が実行を始めて初めて記録する。コンストラクタの初期化リストや、引数の評価で投げた呼び出しは取れない。
- 突き合わせるのは**呼び出しの辺**で、**データの流れ**ではない。辺があっても、流れが見つかるかは別(`flows: not_checked` と同じ線)。

## 5. 試した結果(動物園の Dart と、自前の curated)

グラフは、元の cells から `rivus index` で作った(729 関数、1221 呼び出し点、1265 辺)。stack は、`zoo_test.dart` の 187 ケースを 1 回ずつ。

| | 方法 A(sink の stack) | 方法 B(全部の入口) |
|---|---|---|
| 記録した stack | 249(sink の呼び出し) | 816(入口 567 + sink 249) |
| 別々の観測した辺 | 185 | 335 |
| グラフにある(`ok`) | 146 + SDK 4 | 283 + SDK 7 |
| **グラフにない(`no_edge`)** | **35** | **39**(+ SDK の参照なし 6) |
| 位置や名前が引けない | 0 | 0 |
| `@miss` 13 行のうち、同じファイルに「グラフにない辺」がある行 | 9 | 9 |
| `@miss` のないファイルの「グラフにない辺」 | 16 | 26 |

- **既知の `@miss` は出る**。動物園の、呼び出しが未解決の `@miss`(`dyn/func_field`、`dyn/func_map`、`dart/tearoff_instance`、`dart/super_mixin_impl`、`clos/partial_callers`)は、すべて「グラフにない辺」として出た。出なかった 4 行は、辺の欠落ではない種類のもの(`state/global_chain` の `recursion_approximation` 2 行、`dart/patterns_record` の `silent` 2 行。パターンの流れと、不動点の打ち切り)。
- `bench/dart-curated`(自前のコード。runner だけ作業用に足した。方法 A のみ): 131 の stack、178 の辺、グラフにない辺 16。`@miss` 27 行のうち 15 行が、同じファイルに「グラフにない辺」を持つ(`callbacks.dart` の `captured_fn`、`capture.dart` の `relay_cap_*`、`classes.dart` の `emitter_*`、`limits.dart`、`across.dart`、`dynamic_calls.dart` など)。出なかった 12 行(`nesting.dart`、`futures.dart`、`errors.dart`、`iterables.dart`、`tearoff.dart`)の理由は**確かめていない**。推測: 呼び出しの辺が sink の stack に載らない形(クロージャを返して、呼ぶ所と sink が別)、非同期(4 節)、例外。**方法 B を curated に当てるのは、まだ**(当てれば、推測が合うかが分かる)。
- **新しい欠落の候補**(`@miss` のないファイル。方法 B で 26 件、1 件ずつ見る前の数)。例: 返したクロージャをその場で呼ぶ(`clos/returned`)、リストや変数に入れたクロージャを呼ぶ(`clos/stored`、候補 0 の `value` 呼び出し)、メソッドの tear-off(`dyn/method_value`)、フレームワーク(`Navigator.pushNamed`)が呼ぶコールバック、`toString` の暗黙の呼び出し。動物園の既存の注釈が「見つかる」としているものも含む(辺がなくても、taint は作った所で扱うため。1 節)。**辺の欠落であって、taint の見逃しとは限らない**。
- **Issue #77、#81、#88、#97 の形**は、動物園にも curated にも `@miss` として入っていないので、この突き合わせでは確かめていない(#97 の `call` メソッドの形は、動物園にセルがない)。これらの形を足せば、同じ道具で見えるはず、という見込みで、**確かめてはいない**。

結論: **方法はグラフの欠落を見つけられる**。方法 B のほうが見える辺は多い(185 → 335)が、`@miss` のうち見つけた数は同じ(9 / 13)で、新しい候補は B のほうが多い。選ぶなら **方法 B を本命**にする(sink の stack に載らない辺が見える。実装は、構文だけの書き換えで、依存の追加がない)。A は、stack を 1 本持つだけで済む軽い補助。

## 6. 設計(案)

1. **記録**: 方法 B。コピーした cells を、`instrument.dart` で書き換え、harness で走らせ、`(ケース、callee の stack の先頭 4 行)` を JSON に書く。元のコードと CI の動物園は変えない。
2. **比べる**: `compare.py` を、小さい Go のコマンド(`rivus observed-compare`、または `cmd/rivus` のテスト)に置き換える。グラフは `rivus index` の SQLite。出力は、辺ごとの `ok` / `no_edge` / `no_callsite` / `callee_unresolved` と、ケース。
3. **使い方**: 動物園で、定期的に(CI の毎回ではなく、重い層として。`DESIGN-zoo.md` の定期の実行に並べる)。出た `no_edge` は、1 件ずつ「rivus の欠落」「注釈にない既知の欠落」「方法の限界(4 節)」に分け、欠落なら **Issue と、動物園のセル(`@miss`)**にする。方法の限界は、除外の一覧に、理由つきで書く。
4. **既知の `@miss` の確認に使う**: 欠落が直ったなら、観測の辺が `ok` に変わる(`@miss` を外す根拠が、もう 1 つ増える)。

## 7. 第三者のコードを走らせるときの隔離(案。まだ走らせない)

**今回は、第三者のパッケージのテストを一切実行していない**(`bench/zoo-dart` と `bench/dart-curated` だけ)。Dart には、隔離がまだない([PRINCIPLES.md](PRINCIPLES.md) 8 節)。第三者のコードの実行は、次の隔離ができて、相談役のレビューを通ってから。

- 実行は、**コンテナの中だけ**(Rust の隔離の設計、[rust-isolation.md](rust-isolation.md) と同じ形): ネットワークなし、読み取り専用のルート、書き込めるのは作業用の一時領域だけ、root でない、メモリ・時間・プロセス数・出力量の上限、ホストのファイルとソケットをマウントしない。
- **取得と実行を分ける**: `dart pub get`(ネットワークが要る)は、別の段で、取得だけを行い([DESIGN-fetch-network.md](DESIGN-fetch-network.md) の、ネットワークを絞る案と同じ)、結果をボリュームに置く。テストの実行の段は、ネットワークなしでそのボリュームを読む。
- 書き換え(`instrument.dart`)は、**構文を読んで文字を差すだけ**で、対象のコードを実行しない。ただし、書き換えた結果を走らせるのは実行なので、隔離の中だけ。
- 記録(stack)は、コンテナの外に、**サイズの上限つきのファイル**として出す。中身は、対象のコードが決める文字列(関数名、パス)なので、読む側は**信用しない入力**として扱う(長さ・文字の検査、JSON 以外は受けない)。
- テストが外へ出ようとする(ネットワーク、`Process.run`)のは、**そのこと自体が観測の対象外**。失敗として数え、結果に出す。

## 8. Go と Rust の見通し

- **Go**: 方法 B と同じ形ができる。`go/ast` で、全部の関数の先頭に `rivusEnter()` を差し、`runtime.Callers` で呼び元の PC を取る。`runtime.Frame` の `Function` が `pkg.(*T).M` の形で、rivus の Go の関数の symbol とほぼ同じなので、**ID の合わせは Dart より楽**。呼び出し点は、ファイルと行(桁は取れない)。`go test -cover` は文の網羅だけで、辺は取れない。
- **Rust**: `std::backtrace::Backtrace` を入口で取る方法はあるが、**名前は単相化とマングルの影響を受け**、`{{closure}}` の番号もグラフの ID とは別。ID の合わせが、3 言語で最も難しい。LLVM のカバレッジ(`-C instrument-coverage`)は、関数の実行の有無だけで辺は取れない。取り組むなら、Dart と Go の結果を見てから。
- どの言語も、**同じ比べ方**(呼び出し点の位置 → 呼び先の関数 ID が、グラフの辺にあるか)を使える。違うのは、記録と ID の合わせだけ。
