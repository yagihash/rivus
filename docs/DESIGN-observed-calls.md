# 観測した呼び出しとの照合

> - 状態: **案**(初版)。Dart では最小の試行を 1 回通した(5 節。CI には載せていない)。Go は、まだ試していない(確認していないことは、その旨を書く)。
> - 確認: Dart の試行は 2026-11-22、926ac45 に載せた `bench/zoo-dart/observed/` を実際に実行した数字。セルの数(3 節)は 2026-11-23 に、コードを grep で数えた。
> - 関連: [DESIGN-zoo.md](DESIGN-zoo.md)(zoo は、実行で正解の裏付けを取る)、[GRAPH.md](GRAPH.md)(照合する相手のグラフ)、[ROADMAP.md](ROADMAP.md) 1 節、[issues/183-interceptor-handler-call-has-every-handler-as-candidate.md](issues/183-interceptor-handler-call-has-every-handler-as-candidate.md)。

## 1. 目的

実際にコードを実行して、実際に起きた呼び出しを記録する。それを、rivus の静的なコールグラフ(`rivus index` が作る SQLite の `callsites` と `edges`)と比べて、次を調べる。

1. **取りこぼし(最優先)**: 実行時にあったのに、静的なグラフにないエッジ。グラフにないエッジの先へは、流れ(taint)が届かないことがあるので、サイレントな見逃し(偽陰性)の候補になる。
2. **過大(情報として)**: 静的なグラフにあるのに、実行では起きなかったエッジ。#183 の型(候補が登録した全部のハンドラになる)の大きさを知る材料になる。実行しなかった枝にあるだけかもしれないので、取りこぼしほど強くは言えない。

zoo は**知っている形**の正解を守る。この照合は**まだ知らない形**を見つける。「rivus が報告したことが正しいか」ではなく、「実際に起きたのに、rivus が報告しなかったこと」を探す。

エッジが欠けても、taint の結果が変わるとは限らない(例: 返したクロージャは、作った所で「呼んだものとして」扱うので、呼び出しのエッジがなくても流れは見つかる。`clos/returned`)。ただし `rivus graph` はエッジだけを見るので、エージェントには欠けて見える。どちらに効くかは、エッジごとに別に見る。

## 2. 何を、どう記録するか

### 2.1 観測するもの

**呼び出しのエッジ**: 呼び出し元の関数 + 呼び出しの位置 → 呼び出し先の関数。とくに、動的ディスパッチ(インターフェース、関数値、クロージャ、リフレクション)で、**実際に選ばれた呼び出し先**。静的に決まる呼び出しは、比べても得るものが少ないが、ID の合わせ(4 節)が合っているかの確認になる。

### 2.2 Dart の選択肢

| 方法 | 長所 | 短所 | 判断 |
|---|---|---|---|
| A: sink を呼んだ所の `StackTrace.current`(zoo の harness に実装済み) | 元のコードを変えない。依存の追加なし | sink に届く呼び出しの連なりだけ | 補助 |
| B: コピーした cells の全部の関数の入口に `rvEnter()` を差し、stack の先頭 4 行を保存(`instrument.dart`。試行済み) | 実行された入口すべてが見える。構文だけの書き換えで、型を見ない | コピーが必要。差した分、同じ行の桁がずれる。入口の前に失敗するものは見えない | **本命** |
| C: VM サービスのカバレッジ(`--enable-vm-service`、`getSourceReport` の `Coverage`、`dart test --coverage`) | 書き換えなし | 行や関数が実行されたかだけで、**誰が誰を呼んだかは分からない**。エッジの照合にならない(zoo の文の網羅には、すでに使っている) | 使わない |
| D: VM サービスの CPU プロファイル(呼び出しの木) | 書き換えなし | 標本を取るので、短い呼び出しを落とす。**落とした=取りこぼしなし、とは言えず**、照合に使えない | 使わない(**推測**。試していない) |

### 2.3 Go の選択肢

| 方法 | 長所 | 短所 | 判断 |
|---|---|---|---|
| A: `go/ast` で、コピーの全部の関数の先頭に `rivusEnter()` を差し、中で `runtime.Callers` を呼んで、呼び出し元の PC を取る | 実際の呼び出し先の関数名が出る。インライン展開された関数も `runtime.CallersFrames` で正しく出る。Dart の B と同じ形で、作りが揃う | 位置は行まで(桁は取れない)。コピーが必要。ジェネリクスと、自動生成のラッパー(`T.M-fm`、値レシーバの `(*T).M`)の名前の扱いが要る | **本命** |
| B: `go build -toolexec` で、コンパイルの前に、書き換えのツールを挟む | 元のソースを触らず、ビルドの途中で書き換えられる | 実装が A より大きい(`go/ast` で書き換える中身は同じ)。ビルドのキャッシュの扱い、CI との相性が増える | 後で検討(A で足りれば不要) |
| C: `-cover`(文のカバレッジ。zoo が `cmd/observe` で、すでに使っている) | 書き換えなし | 実行したブロックだけで、**誰が誰を呼んだかは分からない** | 使わない(文の網羅の確認には、すでに使っている) |
| D: `pprof` の CPU プロファイル | 書き換えなし | 標本を取るので、短い呼び出しを落とす。取りこぼしの判定に使えない | 使わない |
| E: `go test -trace`(`runtime/trace`) | 書き換えなし | ゴルーチンやスケジューラの出来事で、関数の呼び出しのエッジではない | 使わない |

**どちらの言語も、書き換えは「構文を見て、文字を差すだけ」で、対象のコードを実行するのは、あとの実行の段階だけ。**

### 2.4 Rust

`std::backtrace::Backtrace` を入口で取れるが、名前は単相化とマングルの影響を受け、`{{closure}}` の番号も、グラフの ID とは別になる。ID の合わせが 3 言語でいちばん難しい(推測。試していない)。LLVM のカバレッジは、関数の実行の有無だけで、エッジは取れない。Dart と Go の結果を見てから。

## 3. どの言語から始めるか

**推薦: Dart から。ただし、Go を同じ設計で続けて作る(2 段目)。**

理由(確認したこと):

- **取りこぼしが多いのは Dart**。値の呼び出しのうち、候補が 0 件のものは、zoo-dart 85 件中 38、zoo-go 50 件中 2([ROADMAP.md](ROADMAP.md) の指標。2026-11-22 に取った表)。この照合は取りこぼしを見つける道具なので、取りこぼしの多い言語に使うほうが、見つかる量が多い。
- **Dart は、最小の試行がもう通っている**(5 節)。方法が取りこぼしを見つけられることは、確認済み。新しく作るのは、一般化と Go への移植。
- ROADMAP が Dart を先にしている(一番対応の薄い言語で一番効く、という判断)。

理由(Go を後にする根拠と、Go の良い点):

- Go の ID の合わせは、Dart より楽なはず(`runtime.Frame` の関数名が、rivus の Go の symbol にほぼ近い。**推測。まだ照合していない**)。2 段目で、設計の変更なしに載るはず。
- **#183 の確認は、Go でないとできない**(7 節。memos の gRPC は Go)。だから Go は、取りこぼしの発見だけでなく、#183 の道具としても必要で、Dart のあとすぐに続ける。
- Go の zoo には、`bench/zoo-go/cmd/observe`(`-tags zooexec`)があり、全ケースを 1 回実行する枠は、すでにある。ただし、これは **sink の値**を記録するもので、呼び出しのエッジは記録しない(`main.go` は、`mark.Run` の結果の hits を書くだけ)。エッジの記録は、新しく足す。

### zoo の、動的ディスパッチを含むセルの数

数え方: `bench/*/cells` を grep した数(ざっくり。形が複数あるセルは 1 つと数える)。

| | セルの全体 | `dyn/` と `clos/` のセル | インターフェース、関数値、リフレクションのどれかをコードに含む |
|---|---|---|---|
| Go(`bench/zoo-go/cells`) | 77 ディレクトリ | 34(`dyn` 23、`clos` 11) | 26(インターフェースの宣言 10、関数値の型・リテラル 16。reflect はセルに 0) |
| Dart(`bench/zoo-dart/cells/lib`) | 115 ファイル | 33(`dyn` 19、`clos` 14) | 44(`abstract class` / `implements` / `mixin` 13、`Function` と `=>` と `dynamic` を含む 38。重なりあり) |

どちらも、動的ディスパッチを含むセルは、3 割から 4 割。照合の対象として、量は足りる。Go の reflect のセルは無いので、リフレクションは、今は照合の外(分類は 4 節)。

## 4. 比べ方

### 4.1 静的グラフから、エッジを取り出す

`rivus index -graph <file>` が作る SQLite を、読み取り専用で開いて、SQL で取る。**新しいコマンド(`rivus callgraph` のようなもの)は、今は足さない。** 必要な列は、すでにある。

- `callsites`(`func_id`、`file_id`、`line`、`col`、`kind`、`callee`、`ncand`)と `edges`(`callsite_id`、`from_func`、`to_func`、`kind`、`ncand`)、`funcs`(`fid`、`symbol`、位置、`has_body`)。
- `edges.kind` で、静的 / インターフェース / 関数値(`value`)を分けられる。`ncand` が、その呼び出し点の候補の数(過大の指標)。
- 参照(`refs`)は、エッジではなく、別の表。SDK が渡されたクロージャを呼ぶ場合などの、補助に使う(5 節の `sdk ok` / `no_ref`)。

### 4.2 正規化

観測を、グラフに合わせる。

- **関数**: 観測の関数名 → rivus の `funcs.fid`。Dart は、ライブラリ(`#` の前)と、`#` の後の名前で結ぶ。クロージャは `vuln.<anonymous closure>` と `vuln$1` を、親の名前と始まりの位置で結ぶ(取り違えうる。試行では偽の欠落は出なかったが、保証はない)。Go は `pkg.(*T).M` と symbol で結ぶ(**まだ試していない**)。
- **呼び出し点**: Dart の VM が示す桁は名前の先頭、グラフの桁は引数の `(`。**同じ行で、桁が stack 以上の最小のもの**を取る。Go は桁が取れないので、**行まで**で合わせ、同じ行に複数の呼び出し点があれば、そのどれかが当たれば合うとする(行が同じなら「あるエッジを見逃した」は言えるが、同じ行の別の呼び出しとの取り違えは見えない)。
- 引けないものは、捨てずに**別に数える**: `no_callsite`(呼び出し点が引けない)、`callee_unresolved`(呼び出し先の関数が引けない)。

### 4.3 取りこぼしの分類

`no_edge`(グラフにないエッジ)が出たら、1 件ずつ、次のどれかに分ける。

| 分類 | 意味 | 扱い |
|---|---|---|
| 動的ディスパッチ | インターフェース、関数値、クロージャの呼び出し先が、グラフの候補にない | **rivus の取りこぼし**。課題とセル |
| リフレクション | `reflect`、`dart:mirrors` 相当で呼ばれた | 今は照合の外(9 節の 6。zoo にセルがない。課題にする) |
| コード生成 | 生成されたコードの呼び出し | 生成物が解析の入力に入っているかを見る |
| 別のパッケージの関数 | 依存の関数(`has_body = 0` か、解析の範囲外) | 範囲の設定の問題。取りこぼしとは別に数える |
| SDK / 標準ライブラリの中 | `forEach` などが、渡されたクロージャを呼ぶ。観測は「SDK の関数 → クロージャ」で、グラフは「呼び出し点 → SDK」と参照 | エッジでは比べず、「そのクロージャへの参照があるか」を見る |
| extractor の限界 | 呼び出し点の形(tear-off、`call`、getter、暗黙の `toString`)が、グラフでは別の形 | 1 件ずつ、誤りか形の違いかを決める |
| 方法の限界 | 非同期の境目、入口の前、実行しなかった枝(5 節の限界) | 除外の一覧に、理由つきで書く |

### 4.4 出力の形(課題に書く一覧)

取りこぼしごとに 1 行: **呼び出し元(関数 + 位置)、呼び出し先(関数)、分類、理由、見つけた根拠(どのケースの実行か)**。分類が「rivus の取りこぼし」のものは、課題と zoo のセル(`@miss`)にする。方法の限界は、除外の一覧に理由つきで書く。

## 5. Dart で試した結果(2026-11-22)

グラフは、元の cells から `rivus index` で作った(729 関数、1221 呼び出し点、1265 エッジ)。stack は、`zoo_test.dart` の 187 ケースを 1 回ずつ。手順は `bench/zoo-dart/observed/README.md`。

| | 方法 A(sink の stack) | 方法 B(全部の入口) |
|---|---|---|
| 記録した stack | 249 | 816 |
| 別々の観測したエッジ | 185 | 335 |
| グラフにある(`ok`) | 146 + SDK 4 | 283 + SDK 7 |
| **グラフにない(`no_edge`)** | **35** | **39**(+ SDK の参照なし 6) |
| 位置や名前が引けない | 0 | 0 |
| `@miss` 13 行のうち、同じファイルに「グラフにないエッジ」がある行 | 9 | 9 |
| `@miss` のないファイルの「グラフにないエッジ」 | 16 | 26 |

- **既知の `@miss` は出る**。呼び出しが未解決の `@miss`(`dyn/func_field`、`dyn/func_map`、`dart/tearoff_instance`、`dart/super_mixin_impl`、`clos/partial_callers`)は、すべて出た。出なかった 4 行は、エッジの欠落ではない種類(`state/global_chain` の `recursion_approximation` 2 行、`dart/patterns_record` の `silent` 2 行)。
- `bench/dart-curated`(方法 A のみ): 131 の stack、178 のエッジ、グラフにないエッジ 16。`@miss` 27 行のうち 15 行が出た。出なかった 12 行の理由は**確かめていない**。推測: sink の stack に載らない形、非同期、例外。方法 B を curated に適用すれば確かめられる。
- **新しい欠落の候補**(`@miss` のないファイル。方法 B で 26 件。1 件ずつ見る前の数): 返したクロージャをその場で呼ぶ、リストや変数に入れたクロージャを呼ぶ、メソッドの tear-off、フレームワークが呼ぶコールバック、`toString` の暗黙の呼び出し。**エッジの欠落であって、taint の見逃しとは限らない**。
- #77、#81、#88、#97 の形は、zoo にも curated にも `@miss` として入っていないので、この照合では確かめていない。

結論: 方法は、グラフの欠落を見つけられる。方法 B のほうが見えるエッジが多い(185 → 335)。

### 5.1 数えられないもの(方法の限界)

- **SDK の中**: `List.forEach` などが、渡されたクロージャを呼ぶエッジは、「SDK の関数 → クロージャ」で、グラフとは形が違う。参照の有無で見る。
- **非同期の境目**: `await` のあとの再開、`Future.then`、`Timer`、`scheduleMicrotask` で呼ばれたクロージャは、stack が切れて、元の呼び出し元が見えない。
- **tear-off と暗黙の呼び出し**: tear-off、`toString` の文字列補間、`call`、getter は、呼び出し点の形が違う。1 件ずつ見る。
- **実行されなかった枝**: zoo は文の網羅が 100% になるよう作ってあるが、curated は違う。実行しなかった呼び出しは、何も言えない。
- **入口の前**: 関数が実行を始めて初めて記録する。コンストラクタの初期化リストや、引数の評価で投げた呼び出しは取れない。
- 照合するのは**呼び出しのエッジ**で、データの流れではない。

## 7. #183 との関係

#183 は、呼び出し先の候補を絞る(リクエストの型、登録の対応、モデル)。絞ると、**実際に起きる呼び出しを消してしまう**危険がある。この仕組みは、その確認に使う。

- **確認の方法**: 絞る前と後で、同じ観測(同じ実行)を、同じように比べる。**後で `no_edge` が増えていれば、絞ったせいで、実際に起きる呼び出しを消した**ことになる。増えなければ、観測した範囲では、消していない(実行しなかった枝は、何も言えない)。
- **過大の指標**: 同じ呼び出し点で、静的な候補の数(`ncand`)と、観測した呼び出し先の数を並べる。絞った後に、候補の数が下がり、観測した呼び出し先が残っていれば、絞りが効いている。
- **前提**: zoo に、#183 の形(ハンドラを関数値にして、interceptor に渡し、`handler(ctx, req)` と呼ぶ)の**自前のセル**が必要。今の `dyn/http_middleware_chain`(2026-11-24 に中身を確認)は、`logging` が `inner` を 1 つだけ包む形で、複数のハンドラを登録して、**どのハンドラが実際に呼ばれるか**を区別する形ではない。複数のハンドラを登録し、interceptor 越しに 1 つを呼ぶセルを足す(今の動作で、実在しない経路が出るなら `@fp @ref(#183)`)。足すセルは、自前のコードに限る。公開の grpc のパッケージを実行する必要はない。
- 2 つ以上の言語にまたがる(Go、Dart、Rust)ので、Go のほかは、Dart から順に。Rust の絞り(ADR-079)の確認は、Rust の記録の方法ができてから。

## 8. 実行の範囲(安全)

- **zoo は、手元で実行してよい**。自分で書いたコードで、外へ出る処理を持たない。`bench/zoo-go/cmd/observe` と `bench/zoo-dart/exec` は、すでにそうしている。
- **公開のパッケージ(memos など)**: 取得は可。**実行は、ユーザーに確認が必要**。Go と Dart には隔離がなく([PRINCIPLES.md](PRINCIPLES.md) 8 節)、実行は、そのコードに、自分の権限で何でもさせることになる。Rust だけは、macOS のサンドボックスの下([DESIGN-macos-sandbox.md](DESIGN-macos-sandbox.md))。
- **確認の取り方**: 実行の前に、ユーザーに、次を示して、答えを得る。
  1. **何を**: パッケージの名前とバージョン(コミット)、実行するコマンド(例: `dart test`、`go test ./...` のどのパッケージか)。
