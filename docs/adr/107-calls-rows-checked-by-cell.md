# ADR-107: パッケージの `calls:` の行は、実行との照合ではなく、解析の水準のセル(`checked_by: cell`)で確認する(弱い。2026-11-23)

- 状態: 有効
- 関連: MODELING.md 3 節、MODEL-RUNBOOK.md
- 状態の詳細: 第三者のコードを実行しない。補い: 行を通るセルが必須、モデルを空にするとセルが落ちる確認、本物のパッケージでの照合(DESIGN-package-models.md 6.8 (b))。Dart と Rust のパス解決は最初の実際の行の PR で確認
- 要旨: 標準ライブラリの行は、今までどおり実行で確認

**背景:** `calls:` の行は、実行の確認の道具(`TestZooCallbacks*`)が、標準ライブラリの関数を実際に呼んで照合する(ADR-091 系の仕組み)。パッケージ(第三者のコード)の行は、どの道具も呼ばないので、検査(`uncheckedCalls`)に通らず、手順書の `calls:` の段が入れられなかった。

**決めたこと:**
1. **第三者のコードを実行しない**。道具は標準ライブラリの行だけを対象にし、パッケージの行を道具に対応させない。
2. パッケージの行は、各行に `checked_by: cell` を書く(標準ライブラリの行に書くと失敗)。代わりに、その行の関数を呼び、`@sink`(`none` 以外)か `@miss` のマークがあるセルがあることを、`TestCallsRowsAreHeldByCells` が確認する。宣言がなければ、動作も出力も変わらない。書式は MODELING.md 3 節。
3. **これは弱い確認である**: 実行(ライブラリが実際にすること)ではなく、モデルと解析の整合を見るだけ。モデルがライブラリの実際と違っても、セルは通る。
4. **補い**: (a) 行を通るセルが必須。(b) モデルを空にするとセルが落ちることを、手順書の確認の項目に足す(セルがモデルを実際に使っていることの確認)。(c) あとで、本物のパッケージでの解析だけの照合を足す(DESIGN-package-models.md 6.8 の (b))。
5. **未確認**: Dart と Rust のファイルパスの解決(IR の位置のファイルから、セルのファイルを引く部分)は、Go でしか確かめていない。最初の実際の行(dio の interceptor、または gin のミドルウェア)を足す PR で確認する。

**しないこと:** パッケージの取得物の実行、既存の ADR の書き換え。
