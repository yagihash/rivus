# ADR-052: `not_from_entry` に、起点に入っていないものの説明を添える（つなぎ）

- 状態: 有効
- 関連: -
- 状態の詳細: 073 が拡張

**背景:** finding の `reachability: not_from_entry` は、「経路のどれかの関数が、起点（`main`、`init`、Dart の `main`、Rust の `entry_fn`。なければ exported）から届かない」と報告する。**フレームワークが呼ぶメソッド（依存の型のメソッドの上書き）や、フレームワークに登録するハンドラは、起点に入っていない**（依存を読まない Dart と、依存を読まないときの Go / Rust では、フレームワークの側が読まれず、そこから呼ぶエッジもない）。読む人が「死んだコード」と読むと、誤り。C-4（`overrides` のエッジ）が入るまでのつなぎ。

**決めたこと:** `not_from_entry` の finding に、説明の文字列 `reachability_note`（`taint.NotFromEntryNote`）を付ける（新しいフィールド。`from_entry` と、起点が分からないとき〔`reachability` が無いとき〕には付けない）。内容: 「`not_from_entry` はコードが死んでいるという意味ではない。フレームワークが呼ぶ関数（依存の型のメソッドの上書き、フレームワークに登録したハンドラ）は、ここでは起点に入っておらず、読まなかった依存のコードは、それを呼ばない」。全言語で同じ文字列（言語ごとに分けると、依存を読んだかどうかの情報が、解析の側に必要。C-4 で、エッジとして入れるときに、説明ごとなくす）。finding の集合も、`reachability` の値も変わらない。出力の形は、フィールドの追加だけ。
