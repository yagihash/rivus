# ADR-116: モデルも本体もない関数に関数値を渡したとき、その関数値は呼ばれ、返り値が結果に届くと見なす(2026-11-23)

- 状態: 有効
- 関連: ADR-059(クロージャのキャプチャを作った場所で適用する)、ADR-008(不確実性の種類)、docs/MODELING.md 3(`calls:` の行)、docs/issues/76
- 要旨: `assumed_call` の uncertainty つきで、結果に届く。行と本体があるときは、今までどおり行と本体が決める

**背景:** モデルも本体もない関数(標準ライブラリの `(*regexp.Regexp).ReplaceAllStringFunc` など。標準ライブラリの本体は読まない)に、値をキャプチャしたクロージャを渡し、呼び出しの結果を使う形で、値が結果に届かなかった。理由は 2 つ。(1) モデルのない呼び出しの既定は「引数のすべてが結果に出る」で、クロージャ自身の値はキャプチャを持たない(キャプチャは束縛として別に持つ)ので、クロージャの中の値は結果に出なかった。(2) キャプチャは、クロージャを作った場所で、呼ばれたものとして適用される(ADR-059)が、そのとき返り値は適用しない(返り値は「呼ぶ場所のもの」。uncertainty にも「what it returns is not applied」と書いた)。呼ぶ場所が、見えないライブラリの中なので、返り値を受け取る場所がどこにもなかった。`unmodeled_library_call` の uncertainty は出るが、どのクロージャが落ちたかは言っていなかった。Dart も同じで、実装が 1 つも分からないインターフェースのメソッド(`Zone.run` など)が、同じ形で落ちた。

**決めたこと:**
1. **対象の呼び出し**: モデルの行がなく(`HasModel` でない。`calls:` のない行でも「行がある」)、source の規則もなく、本体もない呼び出し。具体的には、本体のない静的な呼び出し先(外部、`unmodeled_library_call` になるもの)と、実装が 1 つも分からないインターフェースのメソッド。FFI、リフレクション、読めなかった本体(`dependency_body_unread` など)、本体を読まない宣言のあるパッケージ(bodyreplaced.go が扱う)は対象にしない。
2. **足すもの**: そのような呼び出しに、プログラムが本体を持つ関数値(クロージャ。1 から 4 個。`callbacksOf`)が引数で渡されたとき、その関数値は呼ばれたと見なす。**ほかの引数と(あれば)レシーバの、どれもが、関数値の、どの引数にも届きうる**(和集合。ライブラリが何を渡すかは分からないので、位置の対応は置かない。ほかの引数 1 つずつを、全部の引数に結んで、関数値の要約を適用する。数と bool の引数は、これまでどおり何も運ばない)。結果がある呼び出しは、関数値の返り値が結果に届く(`ret: result`)。**結果のない呼び出しも対象**: 引数やレシーバが関数値の引数に届くので、関数値の中の sink に届く。行の形で `callbackFuncs`(順序の依存)、`callBindings`(キャプチャの束縛)、`givenToModel`(作った場所での二重の適用の回避)にも効かせるが、適用は `noModelCallbacks` が自分で行い、モデルの行は参照しない(経路の step に `model` は付かず、uncertainty だけが「行がなく、既定で見なした」と言う)。引数への書き込みや、引数に返り値を出すことはしない(最小)。
3. **uncertainty**: `assumed_call`。「どの関数のどの引数に、どの関数値が渡され、呼ばれて、返り値が結果に届くと見なしたか」を detail に言う(関数値の ID を含む。「ほかのどの引数も、どの引数にも届きうる」ことも言う)。既存の `unmodeled_library_call` の uncertainty は変えず、両方が出る。`assumed_call` は不確実性の「閉じた種類」(ADR-008)のままで、新しい種類は足さない。
4. **行と本体が勝つ**: モデルの行がある呼び出し、本体を読む呼び出し(依存の本体を含む)は、何も変わらない。規則の追加で、その関数の行を書けば、この既定は使われない(`docs/MODELING.md` の「本体もモデルもない関数に関数値を渡したとき」の項)。
5. **関数値が分からないとき**(パラメータ、メモリから読んだ値): 何もしない。結果は、今までどおり引数のすべてから作られる(引数に関数値が含まれる値なら、それが届く)。
6. **3 言語で同じ**: 核の処理で、言語を分けない。Go、Dart、Rust のセル(`F/clos/to-nomodel`。結果のある形と、結果のない形)で確認した。
7. **精度の行**: 同時に、最初に見つかった形の関数、`(*regexp.Regexp).ReplaceAllStringFunc` と `ReplaceAllFunc` に、`calls:` の行を足した(一致した部分を関数に渡し、返り値を結果に置く。実行で行を確かめる `TestZooCallbacksGo` に呼び出しを足した)。`ReplaceAllLiteral` と `ReplaceAllLiteralString` には、置き換えの値と元の文字列が結果に出る行を足した。行がある関数は、この既定の対象ではないので、Go のこの既定は、`testdata/go/cases/nomodelcb`(`lib.Thunk`)と Dart のセルが守る。ほかの、関数値を取る標準ライブラリの関数(`strings` / `bytes` の `*Func`、`slices` の `DeleteFunc` など。行のないものは 100 件を超える)の行は、この PR では足していない(足す行ごとに、実行の確認と、zoo のセルが要る)。

**測定:** go-curated、dart-curated、gogs 2 つ、gin-vue-admin、go-test-bench、gophish、casdoor の軽い層で、finding の増減は 0、経路の変化は 0、`assumed_call` の uncertainty は dart-curated で 33 → 34、gogs で 156 → 157 と 157 → 158、go-test-bench で 23 → 24。時間とメモリは、ばらつきの中(gin-vue-admin 78 秒 → 78 秒、4606 → 4667 MB)。

**しないこと:** 引数や、ほかの出力への書き込みを、関数値の返り値から出すこと。呼ばれない(並行に動く)関数値の返り値を、結果に出すこと(`calls:` の `mode: go` / `defer` の扱いは変えない)。分からない関数値(パラメータ)の扱い。課題 #76 の、本体のあるヘルパーの中の呼び出し、#78(返したクロージャ)、#79(フィールドに持ったコールバック)は、この ADR では直らない(別の原因)。
