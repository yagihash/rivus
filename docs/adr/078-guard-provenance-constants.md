# ADR-078: ガードの出所(provenance)は、定数そのものか定数の単純なコピーだけを断定する。演算を越えるときは畳むか `unresolved`、`zero_value` は書き込みが 1 つも届かないと分かるときだけ

- 状態: 有効
- 関連: ARCHITECTURE 5.6
- 状態の詳細: F4/F5 訂正が本文内; 訂正・追記あり(書き方を保つ)
- 要旨: 誤った注記の中で最も重い、と明記

**背景:** 判定役は `conditional_nodes` の `provenance.resolved`(`literal` / `zero_value`)を、「この呼び出しでは条件の値が決まっている」と読み、サニタイズ済みの側なら流れを捨てる。それで、断定した値が実際と逆だと、本物の流れが捨てられる(誤った注記の中で最も重い)。head で 3 つの形が確かめられた。(1) 単項・二項の演算(`!`、算術)を、オペランドへそのまま素通ししていた(`render(!c.raw, src)` の `c.raw = true` を `true / literal` と報告する。実際の引数は `false`。`level(c.n-9, src)` を `9 / literal`。実際は 0)。比較は定数側だけを除いて、もう一方のオペランドの値を報告していた。(2) フィールドを読む先が、関数内の変数のとき、その変数への丸ごとの代入(関数の結果、`*p` のコピー、配列の要素のコピー)を書き込みと数えず、「誰も設定しない」と見てゼロ値と報告していた。(3) 呼び出しの結果をたどって callee の引数に着くと、その呼び出しの引数ではなく、callee の全部の呼び出し元の引数を混ぜていた。アドレスを取られた変数への、ポインタ越しの書き込みも数えていなかった。

**決めたこと(provenance だけの変更。コアの要約、finding の集合は変えない):**
1. 値を断定してよいのは、定数そのもの、定数の単純なコピー(変数・フィールドへの格納と読み出し、`make_interface`、型表明、callee が返す定数)だけ。
2. 途中に演算(`convert`、単項、二項: 比較を含む)があるときは、オペランドを別々にたどる(`derived`)。オペランドの値は、結果の値としては報告しない(集める枠に入れる)。全オペランドが定数に着き、演算が畳めれば、畳んだ値を `literal`(全部ゼロ値なら `zero_value`)で示す。畳めない(オペランドが `unresolved`、定数でない、演算が分からない、型の大きさが分からない、オーバーフロー、0 での除算)ときは、`depth_limit`(`attributable_to: rivus`)で「演算で計算される値で、定数に畳めなかった」と報告する。オペランドがすでに止まった理由を報告しているときは、それだけにする。畳み方(`provfold.go`)は Go、Rust、Dart の演算子と型名の綴りを受ける。φ が複数の値を運ぶときは、組み合わせ(16 まで)ごとに畳む。
3. `zero_value` は、フィールドへの格納、フィールドの一部への格納、変数の丸ごとの代入のどれも、そのオブジェクトに届かないときだけ。丸ごとの代入のうち、同じ関数の別の変数のコピー(リテラルは別の変数に作ってコピーされる)は、その変数のフィールドをたどる。型のゼロ値の代入は、何も変えない。それ以外(関数の結果、`*p`、配列の要素)は `unresolved`。変数の値を読むとき(`walkAddr`)も、アドレスが渡っていれば `unresolved`。
4. 呼び出しの結果をたどって callee の引数に着いたら、その呼び出しの引数に結ぶ(ほかの呼び出し元の引数は混ぜない)。

**確かめたこと:** `testdata/go/cases/guard/provenance.go`(報告された 7 つの形+アドレスを取られた変数、callee の引数、比較の畳み込み): 否定と算術は畳んだ値(`false`、`0`)、丸ごとの代入と配列の要素は `unresolved`、本当のゼロ値は `false / zero_value`、ポインタ越しの `*pc = true` は `true / literal`(`TestProvenanceTellsNoValueThatIsNotKnown`)。畳み込みの単体テストは、Rust(`i32`、`u32`)と Dart(`int`)の型名も含む(`TestProvenanceFoldsOperations`)。Dart と Rust は同じコアで、`!` と `n - 9` を引数にした小さな例で、`unresolved`(誤った値は報告しない)になることを確かめた。`bench/compare.sh --light`: finding の追加・削除 0、`path@1` の変化 0。軽い層の実コードで断定していた件数は、`literal` が 0、`zero_value` が 2(gogs の 2 つのバージョンで同じノード。`PatchPath` の `repo` に `nil / zero_value`)で、どちらも `unresolved` になった(誤って断定していた数の上界は 2)。

**限界:** 変数の丸ごとの代入は、別の関数の変数のコピーや、構造体の中の構造体の一部の格納は、たどらず `unresolved`(多めに報告しない側)。Dart と Rust は、変数の読み出し(`not followed: *ssa.Slice`)で止まるため、定数を畳む前に `unresolved` になる(今までも値は報告していない)。

**F4 / F5 の訂正(アーキテクチャ助言者のコードレビュー、ADR-078 の続き):** 上の決めたことに、断定の誤りが 2 つ残っていた。(F4) φ を通る循環を何も報告せずに切るので、その上に定数の枝を持つ別の φ があると、不完全な集合を「全部分かった」と報告した(`a := 1; for ... { b := a; if i == 3 { b = 7 }; a = b + 1 }` で `[1, 8]`、`unresolved` は空。実際は 2、3、4、8、9、…)。修正: 値(と、オブジェクトのフィールド)をたどる途中で同じ点に戻ったとき、戻るまでに演算(`derived`)を通っていたら、その枠を失敗(`depth_limit`、「循環が演算を通る」)にする。コピーだけの循環は値を足さないので、これまでどおり何も報告せずに切る。(F5) `zero_value` を、関数のどこにも書き込みがないときだけ報告していたので、読んだ後の書き込み(`v := c.n; c.n = 9` で `9 / literal`、実際は 0)や、片方の枝だけの書き込み(`if k > 2 { c.n = 9 }; v := c.n` で `{9}`、実際は `{0, 9}`)で間違った。修正: 読み出しの地点に**届く**書き込みで決める。読み出しに届かない書き込み(同じブロックの後ろで、戻る経路もない)は数えない。読み出しに至る全部の経路にある書き込み(同じブロックの前、または読み出しのブロックを支配するブロック)があるときだけ、ゼロ値を外す。支配が分からなければ、ゼロ値も候補に入れる(多めに報告する側)。呼び出し元の関数へ進むときの読み出しの地点は、その呼び出し。ポインタ越しのフィールド読み出し(`walkAddr`)も、ゼロ値を報告する(以前は何も報告しなかった)。限界: 全部の枝が書いていても、1 つの書き込みが支配しないなら、ゼロ値が候補に残る(`{9, 0}`)。**確かめたこと:** `testdata/go/cases/guard/provenance.go` に `SteppedInLoop`、`ReadThenWrite`、`WrittenOnOneBranch`、`WrittenOnBothBranches` を足した(期待値は、正しい集合か `unresolved`)。`!c.raw`、`c.n-9`、`getCfg()` の形、`*pc = true`、本当のゼロ値は前と同じ。`bench/compare.sh --light`(F4: 2faa8aa から 9736701、F5: dc811ca から f88be02)で、finding の集合は同じ(追加 0、削除 0、経路の変化 0、不確かさの数も同じ)。実コードの `conditional_nodes` は、gogs の 2 つに計 8 件だけで、どれも `resolved` が空(`unresolved` のみ)で、前後とも同じ。誤って断定していた数の上界は、軽い層で 0。
