# ADR-046: 独自のベンチ（bench/go-curated と bench/go-synth）の位置づけ

- 状態: 有効
- 関連: bench/README
- 要旨: 精度回帰と性能スケールを分ける

**背景:** エンジンの変更のたびに Gitea（約 35 万行）で確かめると、10〜16 分、5〜15 GB かかる。しかも Gitea や gogs には正解がない（ラベルは人が読んで付けたもの）。速さと精度を、別々の小さなベンチで、毎回確かめられるようにする。

**決めたこと:** `bench/` に、言語ごとの 2 種類のベンチを置く（今は Go。Dart と Rust は、同じ形で並べる）。
1. **`bench/go-curated`（精度の回帰。正解つき）。** Gitea、gogs、gin-vue-admin、ech0 の書き方（ハンドラの登録、ミドルウェアの連鎖、ORM、DI、インターフェース越しの呼び出し、クロージャ、関数値、alias 付きのモデル、設定、functional options など）を縮めた、約 20 ファイルのモジュール。「検出すべき流れ」と「検出してはいけない流れ」を、サンプルと同じ注釈（`@source` / `@sink` / `@sink(none)`）で書く。それに、いまのエンジンができないことを、`@miss`（流れがあるのに見つからない）と `@fp`（ないのに出る）で書く。**両側から検査する**（直ったのにマークが残っていたら、テストが失敗する）ので、これは棘（ラチェット）になる。検査は `cmd/rivus/bench_curated_test.go`（`checkCurated`。ディレクトリを受け取るので、Dart・Rust のプロジェクトも同じ検査を使う）で、毎回の `go test ./...` に載る（1〜2 秒）。注釈の数: 検出すべき流れ 22 件（うち `@miss` 1 件: functional options で、クロージャの列を回して構造体のフィールドに書く形が見つからない）、出してはいけない 19 件（うち `@fp` 5 件: コンテキストの `Set` / `Get` のキーの違い 3 件、キャッシュのマップのキーの違い 1 件、switch の許可リスト 1 件）。
2. **`bench/go-synth`（速さ・資源のスケール。生成）。** パラメータ（関数数、呼び出しの深さ、SCC の大きさ、インターフェースと実装の数、実装からの呼び戻し、フィールド数、関数値の表、共有ヘルパーに渡すクロージャ、4 段のパスなど）から、Go のコードを作るジェネレータ（`gen`。同じパラメータなら同じバイト列。テストで確かめる）。サイズ S（1.2 秒、126 MB、171 関数）、M（28.5 秒、810 MB、459 関数）、L（約 127 秒、3.2 GB、911 関数）。測定は `measure.py`（時間、最大メモリ、findings と uncertainties の数、finding の ID の集合のハッシュ。`compare` で前後を比べ、`snapshot` / `check` で `expected/` と比べる）。
3. **運用:** エンジンの中核（`internal/sg`、`internal/sites`、`internal/taint`）に触れたら、`go test ./...`（`go-curated` を含む）と、S と M の前後比較（同じ条件で 2〜3 回。結果は同一でなければならない。速度の変更は特に）。Gitea などの実プロジェクトは、節目だけ。絶対時間は、同時に動くほかの処理で揺れる（M は、マシンが空いているときは 28.4〜28.5 秒、ほかの解析が動いていると 45〜60 秒。メモリは、混んでいても、ほぼ同じ）ので、同じ条件で相対で比べる。
4. **精度を下げて速くしない:** ベンチは、速さの指標を、結果が同一であることとセットで出す（`ids_sha256` と `uncertainties_sha256`）。

**Gitea の形（これをパラメータにした）。** 作業ツリーのバイナリ（2026-11-21、他の変更を含む）で、`-timeout 300s`、12 コア、24 GB のマシンで、1 回測った。
- 段ごとの時間とヒープ（`-v`）: ロードと IR 37.5 秒（ヒープ 5.4 GB）、サイト 1.1 秒、グラフ 8.4 秒（3.7 GB）、taint は 300 秒で打ち切り（`converged: false`、5 パス目）。全体 384 秒、**最大 RSS 15.7 GB**。
- グラフの形: 関数 61,655、段 94、一番広い段に 16,828 個の SCC、**最大の SCC は 3,370 関数**（ADR-044 の追記の時点では 907。この作業ツリーには `internal/valuecalls` などの未コミットの変更があり、関数値の呼び出しの候補が増えた影響の可能性がある。**確かめていない**）。要約: 要素 636 万、ステップ 3.4 億（1 関数あたり約 100 要素）、最大の要約は 14,960 要素。再解析 135,490 回。
- 時間の使い方（CPU プロファイル、335 秒、1,649 CPU 秒）: **GC の走査が約 75 %**（`tryDeferToSpanScan` 34 %、`moveInlineMarks` 24 %、`memclrNoHeapPointers` 8 %、`spanInlineMarkBits.init` 6 %。小さなポインタ付きオブジェクトを 3.7 GB 抱えたヒープ）。解析そのものでは、`applySummary` が累積 24 %。ADR-044 の追記（GC の設定では速くならない、`Elem` の整数化が次の一手）と同じ結論で、今のところ変わっていない。
- 割り当て（`alloc_space`、300 秒で 371 GB）: `newWhyFrom` 11 %、`expandParam` 9 %（累積 17 %）、`unionGuards` 6 %、`collectUncached` 6 %、`state.add` 5 %（累積 12 %）、`goir.conv.emit` 4 %（ロード時）。
- `depth_limit` 1,777 件の出所: `guard_limit`（条件が 5 つを超える）1,548、関数の予算切れ（`-func-timeout`）227、`path_limit`（アクセスパスを深さ 3 で切る。13,332 関数をまとめた 1 件）1、全体のタイムアウト 1。
- 遅い関数（`-v` の `slow function`）: 通知（Notifier）の実装（インターフェースの多数の実装が、呼び出し先の要約を引数ごとに展開する）、`db` のトランザクションのクロージャ（`$1`）、出力 10〜30、ルート 10〜300。
- 大きな SCC の作られ方: 共有ヘルパー（`db.WithTx(ctx, func...)` の形）がクロージャを呼ぶ → 使う側の全体が 1 つの SCC、インターフェースの実装が呼び戻す、リング状の相互再帰。ジェネレータは、この 3 つを別々のパラメータ（`-with`、`-back`、`-sccs`）にした。**SCC の大きさの分布（全体）は、出力にない**ので取っていない（最大だけ）。

**ジェネレータの限界:** サイズは、エンジンが終わらせられる範囲に収めた（L でも Gitea の関数数の 1/60）。1 関数あたりのコストが高い形（フィールドの多い構造体、SCC）なので、小さなコードでも、実コードの 10 倍の大きさに相当する時間がかかる。時間の絶対値は Gitea と比べない。見るのは、前後の比。

**追記（Dart と Rust）:** `bench/dart-curated` / `bench/rust-curated`（巨大 SCC の案 2、つまりヘルパーの要約にコールバックの出力を持たせる変更の前の基準）と、`bench/dart-synth` / `bench/rust-synth`（ジェネレータの計画は共通の `bench/synthplan`、測定は `bench/go-synth/measure.py -lang dart|rust`。extractor の実行は 1 回で、測るのは `rivus analyze -ir` だけ）を足した。検査は `TestCuratedDart` / `TestCuratedRust`（`RIVUS_DART` / `RIVUS_RUST` が無ければ skip。`checkCurated` の流用）。注釈に、Rust でクロージャの呼び出し先が「型が合う全クロージャ」になる過検出を数えるための `@noisy(N)`（その sink に他の source の N 件が届く。数が変わると失敗する）を足した。基準（2026-11-21）: dart-curated は検出 74、`@miss` 32、検出されない 39、`@fp` 4（キャプチャした変数を読み書きするクロージャをヘルパーが呼ぶ形、返されたクロージャ、オブジェクトに持たれたコールバック、エラーと Future が `@miss`）。rust-curated は検出 112、`@miss` 11、検出されない 42、`@fp` 14、`@noisy` 183 件（17 か所。1 つのヘルパーの 2 つの呼び出し元が互いの sink に届く）。synth の S は、Dart が 0.13 秒・21 MB・最大 SCC 4、Rust が 0.35 秒・81 MB・最大 SCC 153（M は 1.3 秒・418 MB・SCC 508、L は 13 秒・1.3 GB・SCC 1030）。Dart は、キャプチャを持つクロージャの流れが失われるので、SCC も findings も小さい（案 2 の後に増えるはずで、それが比べる点）。

**注(のち):** ゲートと変更ごとの確認から Gitea の全体は外れた(Gitea は使わない。大きな実コードは、`bench/compare.sh --big` で名前を指したときと、`bench/explore` の定期の実行だけ。軽い層の `gitea-cut` は、Gitea の 3 件の CVE の切り出し 7 パッケージで、全体ではない)。この ADR の「節目だけ」は、その前の姿。決めたことの ADR は、まだ起こしていない。
