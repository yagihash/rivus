# ADR-095: `rivus index -taint` の JSON の index の既定の書き先を、解析の対象のディレクトリから、利用者のキャッシュに移す(相談役の決定、2026-11-22。互換性を壊す変更。課題 #135)

- 状態: 有効
- 関連: README、GRAPH、AGENT-GUIDE
- 状態の詳細: 相談役の決定(2026-11-22)。課題 #135
- 要旨: 古い既定の場所のファイルは読まない

**決めたこと:**
1. `-o` を省いたときの書き先は、`<対象>/.rivus/index.json` をやめ、グラフのファイル(`graph.db`)と同じキャッシュのディレクトリの `index.json` にする。ディレクトリの決め方は `graph.db` と同じ(`RIVUS_CACHE_DIR`、なければ `os.UserCacheDir()/rivus`、その下に `-C` の絶対パスのハッシュ)。`-graph` を指定しても、JSON の index の既定の場所は `-C` から決まる。書いたパスは標準エラーに出す。`-o` を付けたときは、これまでどおり、その場所に書く。
2. 理由: 信頼できない対象のディレクトリに、rivus が書かない。対象の `.rivus/` は、対象が用意するルールの置き場所(`.rivus/rules`)でもあるので、rivus が書く場所にしない。README と ADR の、グラフのファイルは対象に書かないという説明とも、これで合う。
3. 読む側: `query -index`、`resolve -index`、`models coverage -index` は、パスを明示して読む形で、既定の場所を当てにしていない。変えていない。**古い既定の場所(対象の `.rivus/index.json`)にファイルがあっても、読まない。**
4. 互換性: これまで既定の場所を使っていた人は、`-o` で書き先を決めるか、標準エラーに出るパスを使う。索引のキー、スキーマ、ファイルの中身、解析の結果は変えていない。
