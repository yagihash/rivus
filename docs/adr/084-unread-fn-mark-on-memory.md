# ADR-084: 「読まない関数に渡った」のマークは、メモリの物(変数、指す先)に付け、そこからの値の読み出し(コピー)と、要約を通して運ぶ(`parts` のサイレントな見逃しを直す)

- 状態: 有効
- 関連: DESIGN-field-sinks
- 状態の詳細: 074 の抜けを直す。訂正が本文内; 訂正・追記あり(書き方を保つ)

**背景:** ADR-074 の 3 で、モデルも本体もない呼び出し先に渡された値の根(`opaque`)を覚え、`parts` の sink がその根の下の汚染を見つけたら、`field_imprecision`(`opaque_callee`)で検出する、とした。マークは、呼び出しの**引数の値の根**にだけ付いた。`Params` だけ汚染された構造体 `stmt` の**アドレス**を、読まない関数に渡し、あとで `stmt` を**値で** sink に渡す形(Cloud Spanner の呼び出しは、すべて値渡し)では、アドレスの根は変数のセルで、値のコピー(`load`)は別の根を作るので、マークが sink の引数に届かず、**何も報告しなかった**(実行では、値が SQL に届く)。ポインタを取る sink や、値を渡して値で返す形(`whole_value`)は検出されていた。

**決めたこと:**
1. マークは**セル**(変数そのもの、アドレスの指す先)に付いたまま。そこから**構造を持つ値**(構造体、コンテナ、インターフェース)を作る値の読み出し(`load`、コピー、フィールドや要素の読み出し、φ。`copyLocsNoted` の全体を 1 か所で)は、マークを、作った値の根に運ぶ(`carryOpaque`)。文字列や数値は運ばない(構造の一部を動かす先ではない)。ポインタは、同じセルなので、そのまま。
2. **関数を越える:** 要約(`Summary.Opaque`)が、本体の中で読まない関数に渡った引数の位置を持つ。呼び出し元は、要約を適用するとき、渡した実引数に同じマークを付ける(`markOpaque`。呼び出しがそこで行われたのと同じ)。要約の比較(`signature`)と合流(`joinSummaries`)に入れた。ヘルパーに `&stmt` を渡して、その中で読まない関数が呼ばれる形も検出される。
3. マークは汚染を足さない(ADR-074 の 3 と同じ)。足されるのは、`parts` の sink が、マークのある値の下の汚染を見つけたときの `opaque_callee` の finding だけ。`parts` のない sink と、今の伝播は変わらない。

4. **同じ作業で直した、別のサイレントな見逃し:** モデルの `flows` の `to: argN` が可変長引数のスライス(`row.Columns(&a, &b)`)のとき、スライスのセルに書くだけで、中のポインタの指す先に届かなかった(`bench/gcp` の `ReadColumns`)。`source` の `out:` と同じく、スライスに入れたポインタの指す先(`variadicElems`)にも書く。`testdata/go/cases/variadicdst`。

**確かめたこと:** `testdata/go/cases/fieldsink`: 依存なしの 8 形(ポインタを渡して値で sink を 5 形(初期化、代入、`p := &r` と `*p`、ヘルパーの中、`new`)、値を渡して返す(`whole_value`)、デコイ 2 つ(読まない関数を呼ばない、別の変数に渡す)。5 形は、変える前は検出されなかった(落ちることを確かめた)。`bench/gcp` の `UOpaque`、`UOpaqueAssign` が、`opaque_callee` で検出される。

**限界:** 流れの順序を見ない(解析は、順序を持たない)ので、読まない関数に渡す前にした値のコピーも、マークを持つ(検出する側の誤り。`parts` の sink で、汚染されたアクセスパスが確かでないときの `field_imprecision` だけが増える)。

**訂正(命令の順に依る見逃しを直した):** マークは汚染を足さず `rootVer` も上げないので、前のパスで評価済みの sink の呼び出しは、`callSig` が同じで飛ばされ、あとから付いたマーク(ループの 2 周目、`defer` の sink、読まない関数に渡す前にしたコピーを sink に渡す形)を聞き直さず、何も報告していなかった。修正: (1) `callSig` に、その呼び出しが読むセルの、**自分のマークでないマーク**の数(`markSig`)を入れる。(2) マークは、付けた命令を覚える(`opaqueBy`。2 つ以上、またはマークのあるセルの読み出しで運ばれたものは `multiMark`)。sink は、自分が呼び出しの中で付けたマーク(読まない sink は引数にマークを付ける)を見ない(`touchedByOpaque` の `self`): 見ると、どの sink も、渡されたもののマークで検出されてしまう。つまり、順序に依らず、あるマークが付いた時点で、それを自分のマークでないと見る sink は、もう一度評価される。テスト: `testdata/go/cases/fieldsink` の `LoopMark`、`DeferMark`、`CopyBeforeMark`(変える前は 3 つとも検出されなかった)。「流れの順序を見ない」のは、マークが付いたあとの流れの先を絞らない、という意味(検出する側の誤りは上のまま)。
