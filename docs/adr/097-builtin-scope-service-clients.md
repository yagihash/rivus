# ADR-097: 組み込みモデルの範囲に「外部のサービスのクライアント」を足し、Google Cloud をその範囲の 1 つ目にする(ユーザーの希望を受けた相談役の決定、2026-11-22。ADR-096 を更新)

- 状態: 有効
- 関連: README、ARCHITECTURE 5.5、GCP-MODELS、DART-MODEL-CANDIDATES
- 状態の詳細: ユーザーの希望を受けた相談役の決定(2026-11-22)。ADR-096 を更新。ADR-077 の「例外」は、この範囲で読む
- 要旨: 範囲は 5 つ

**決めたこと:**
1. 組み込みモデルの範囲を、次のとおりに書き直す(ADR-096 の 4 つを置き換える): (a) Google Cloud(Firebase を含む)、(b) 外部のサービスのクライアント(クラウド、認証、決済、メールと通知、検索、監視とエラー報告、メッセージング、ストレージ、BaaS、AI の API。公開の指標の上位)、(c) 標準ライブラリ、(d) 代わりのないパッケージ、(e) pub の人気の上位(Flutter に依存しないサーバ側の基本のパッケージ)。選ぶ基準は、公開の指標(pub.dev の順位、直近 30 日の DL、likes)だけ。特定の利用者が使うものを推測しない。
2. Google Cloud は、「例外」ではなく、(b) の範囲の 1 つ目として位置づける。ADR-077 の「基準ではなく、例外」と、ADR-063 の 2026-11-22 の追記は、この ADR の範囲で読む(本文は書き換えない)。当初の「Google Cloud は手厚く」という指示は、この範囲の最初の対象。
3. 候補の一覧と、進める順は `docs/DART-MODEL-CANDIDATES.md`(3、4、5 節)。公式の SDK と、事実上の標準のコミュニティのものを区別して書く。Flutter に依存するかも書く。Go と Rust の同じ種類の一覧は、Dart のあとで作る。
4. 条件は変えない: 行は一致しなければならない(`docs/MODELING.md` の 5 節)、肯定と否定のフィクスチャ、流れだけのモデルは ADR-092 の条件。理由は ADR-096 と同じ(依存を API の境界のモデルにして、中を読まないことで、動的な呼び出しの合流と解析のコストを下げる)。
