# 設計: グローバルと「共有される場所」を、範囲と粒度を締めて、証拠として見せる

状態: **設計のみ。実装していない。** 数字は、2026-11-21 の main(d12bfe9)で測った(下の「測定」)。**決めたこと**は末尾の「決定」に書いた(アーキテクチャのレビューを受けて、4.1、4.2 b、4.5、4.6 を直した)。関数値の側は [`DESIGN-callouts.md`](DESIGN-callouts.md)(同じ根の、もう 1 つの面)。

## 1. 問題

グローバル(パッケージ変数、Dart のトップレベル変数、Rust の `static`)を通る流れは、**「誰が書いたものを、誰が読むか」の組を失う**。解析は流れに依らない(セルの和)ので、グローバルは「書き手全員の和」を、読み手全員に返す。これは健全側(見逃さない)の選択だが、3 つの形で、本物でない finding と、読む人が評価できない finding を作る。

1. **範囲**: 書き手に、本番で動かない関数(モックの設定、テスト用の関数)が入る。gogs の `SetMockPicture$1`(`Picture = before` の後始末)で、finding が +47 になった(ADR-059。案 D で +2 に戻した。案 D が飛ばしたクロージャは 8: `identity_global_stores`)。根は、下の「粒度」の持ち上げ。
2. **粒度**: 構造体を丸ごと読むとき、フィールドの指す先の要素が、根へ持ち上げられる(`expandParam` が、`collect` の `found.Rel`(どのサブセルにあったか)を捨てる)。マップのキーが定数でも、全部の要素が 1 つの場所に入る(`cont/map-key-vs-value`)。
3. **証拠**: finding が、グローバルを通ったことは言う(経路の `global_var` の注記)が、**そのグローバルに何か所が何を書いたか**は言わない。読む人は、「このフィールドは、1 か所が書いている」のか、「100 か所の和」なのか、分からない。

入口どうしの受け手の状態(Rust の `Arc<AppState>` の `Mutex` のフィールド。`state/receiver-field-across-entries`)も、同じ形の問題(「別の入口が書いたものを、この入口が読む」)で、今は **Rust で出ない**。これを、グローバルと同じ運び方(下の「共有される場所」)に乗せる。

方針は、「**分けようとせず、範囲と粒度を締めて、証拠として見せる**」。書き手と読み手の組を、完全には復元しない(復元するには、実行順とエイリアスが要る)。**見逃しを増やさず**、偽の組を減らせるところだけ減らし、残りは数で言う。

## 4. 設計

### 4.1 範囲: 書き手を、本番のコードに絞る

グローバルの効果(`OutGlobal` と `globalStore` への書き込み)を、**本番のコードの関数に限る**。ただし、**絞る根拠は、「テストだ」という正の証拠だけ**にする(解析の精度は、速度と資源より優先する。起点から届かない関数を外す案は、**採らない**: `Reachable` は、フレームワークが呼ぶメソッドを知らない(ADR-052)ので、本物の書き手を外す)。「呼び元が、読んだ範囲で、すべてテスト」は、**正の証拠ではない**(フレームワークやリフレクションから、読んでいない呼び元が呼びうる)ので、根拠にしない。

証拠は 2 つ。

1. **第 1 段(印がある)**: `_test.go` / Dart の `test/` / Rust の `#[cfg(test)]` と `tests/` の関数(と、その中のクロージャ)は、`-tests` で読んだときだけ解析に入る。この関数の書き込みを、**本番の関数の読みに返さない**(テストは、別のプログラム。テストの中の読み手は、テストの書き込みを読む)。印は、extractor が IR の `Func` に出す(`Test: true`。**IR の追加**)。
2. **第 2 段(シグネチャの証拠。Go)**: **テストの枠組みの型を、引数か受け手に取る関数**は、テストからしか呼べない(その型の値は、テストの枠組みしか作らない)。印は、第 1 段の `Test: true` と同じ欄に、解析の側で付ける(関数の宣言は、`-tests` なしでも見える)。
   - 枠組みの型: `*testing.T`、`*testing.B`、`testing.TB`、`*testing.F`、`*testing.M`。gomock など、ほかの枠組みの型は、規則 `test_only_types:`(型名の一覧)で、**利用者が足す**(組み込みにしない)。
   - **そこからしか参照されない関数**(呼び元と、値としての参照の**全部**が、上の関数か、その中のクロージャ)も、同じ扱い(`SetMockPicture` が呼ぶ後始末のクロージャなど)。**テストでないコードから、1 か所でも参照されていたら、外さない**(読んだ範囲での「全部」は、`valuecalls` の `incomplete`(callouts の段階 1)と同じく、辿れない参照があれば、外さない側に倒す)。
   - **`-tests` なしでも効く**(宣言が見えているので)。gogs の `SetMockPicture(t *testing.T)` は、`-tests` なしで、範囲から外せる。
   - Dart と Rust の同じ証拠(テストの枠組みの型を取る関数)は、言語ごとに、枠組みの型を決めてから足す(最初は Go だけ。Dart / Rust は、第 1 段の印だけ)。
3. 外した書き手は、**黙って捨てない**: finding の `shared_state`(4.4)に、`writers.excluded_test: n` を出す。`-tests` を付けない解析では、「テストの呼び元は読んでいない」ことを `stats` に言う(今の `tests_skipped` と同じ作り)。

gogs の +45 の原因は、`SetMockPicture$1` の `Picture = before`(本番のファイルにあるモック設定)。**第 2 段のシグネチャの証拠で、`-tests` なしでも、範囲から外せる**。粒度(4.2 a)は、これと**二重の守り**になる(テストの枠組みの型を取らないモック設定は、4.2 a が担う)。

### 4.2 粒度

**(a) サブセルの要素を、根へ持ち上げない。** `expandParam` の、`found.Rel` を保つ: 引数の `Loc` の下の、サブセル `/f` にある要素は、呼び元の置き先の `dst.Path + Rel` に置く(今は `dst.Path`)。意味: 「引数の全部」を読む出力(`Param(i, "")`)は、**構造を保ったまま**写る(`G = before` の後始末は、`G` のサブセルを、同じサブセルに戻す。他のフィールドには、何も足さない)。**健全性**: 読む側は、`collect` が、パスの下の全部を読むので、全体を読む読み手は、サブセルの要素を、今と同じに見つける。フィールドを読む読み手は、**そのフィールドの要素だけ**を見る(今は、どのフィールドを書いたものも見る)。パスが `K`(3)を超える分は、`pathTrunc` で切る(粗くなる。`stats` の `coarsened` と、finding の痕跡に残す)。`widen`(24 要素)は、`Rel` を持つ要素を、Rel ごとの全体に合流する(今の `widen` は、`Param` の要素をパラメータごとに 1 つにまとめる)。**案 D(`identityOfGlobal`)は、(a)が入ったら、gogs で `identity_global_stores` を減らして、不要になるかを測る**(取るのは、gogs が +2 のまま、かつ zoo の `restore` のフィクスチャが落ちないとき)。

**(b) 定数のキーで分ける(マップだけ)。** **マップ**(Go の `map`、Dart の `Map`、Rust の `HashMap` / `BTreeMap`)の要素を、**キーごとのパス**(`/[k]`)に置く。**スライス / `List` / `Vec` は、入れない**: 順序を持つコンテナは、切り出し、`append(xs[:i], …)`、並べ替え、`copy`、`reverse`、`remove` で、添字がずれる。`xs[1] = src; sort.Strings(xs); sink(xs[0])` が、定数の添字で分けると、落ちる(見逃し。精度を下げる側に倒さない)。規則:
- キーが**定数**(文字列・整数のリテラルや、定数の畳み込みが決めたもの)の書き込みは、`/[k]`。
- キーが**不明**の書き込みは、`/[?]`(「どのキーでもありうる」)。
- 定数 `k` の読みは、`/[k]` と `/[?]`。**不明のキーの読みは、`/[` の下の全部**(今と同じ)。
- 範囲の読み(`for range`、`len`、全部を返す関数のモデル)は、全部。
- 1 つのセルのキーが **N 個(16)** を超えたら、`/[?]` にまとめる(**粗くした痕跡**: `container_element_imprecision`。今ある種別を使う)。
- **(i) モデルのない関数に、マップを渡したとき**: 関数が、マップに何を書くか分からないので、**`/[?]` への書き込みとして扱う**(どのキーでも読める)。モデルのある関数(`delete`、`maps.Copy` など)は、モデルの言うとおり。
- **(ii) キーの同一性は、(型, 値)**: `1`(整数)と `"1"`(文字列)は別のキー。同じ型の同じ値だけが、同じキー。型が違えば、`/[?]`。
- **(iii) Dart の `Map` で、キーが定数でない型**(オブジェクトのキー。`==` と `hashCode` を持つ型)は、**対象外**(`/[?]` のまま)。定数のキーに分けるのは、文字列・整数・enum の値など、値の同一性が定数で決まる型だけ。

**健全性**: 不明のキーの書き込みを `/[?]` にして、定数の読みが `/[?]` も見るので、見逃さない。偽の組が減るのは、**定数のキーで書いて、別の定数のキーで読む**ときだけ(zoo の `map-key-vs-value`)。**スライス / `List` / `Vec` は、今の「まとめた」ままなので、`cont/slice` のおとり(別の添字)は、過検出(`@fp` + `container_element_imprecision`)として残る**。これは、痕跡つきの過大近似として、受け入れる(見逃しを増やさない側)。
`container_element_imprecision` が、今の「まとめた」痕跡なので、マップで**まとめなかった**ときは、この痕跡が減る(finding の `uncertainties` の数が変わる。受け入れで見る)。

**(c) アクセスパスの切り詰め(`K = 3`)。** 切ったときだけ粗くなる(今も、`coarsened`)。**finding の経路に切り詰めがあったとき**、その finding に痕跡を付けるかを、確かめる(`pathTrunc` の呼び出しが、経路の注記になっているか。測るのは、段階 2)。

### 4.3 合流点になる、少数の型だけをモデルにする

グローバルが「全部の書き手と読み手を混ぜる」のは、1 つのグローバルが、**無関係なデータの置き場**になっているとき。実績: 型の記述子のキャッシュ(ADR-055)、`os.Stderr`(ADR-056)。次の候補(**測って決める**。モデルは、効果が測れてから):

| 候補 | 意味 | 扱い |
| --- | --- | --- |
| `sync.Pool` | 置いたものは、リセットされて、別の用途で取り出される。取り出したものは、置いたものの中身を、読む側が読まない約束 | `Put(x)` は書き込みを捨てる。`Get()` は新しい値(`holds: nothing` の型版) |
| キャッシュ・登録表(`lru.Cache`、`prometheus` の登録表) | キーごとに値が違う | キーで分ける(4.2 b)。分けられないものは、`holds: nothing` を**利用者が選ぶ** |
| `context.WithValue` の値 | キーつきの値の連鎖 | キーが定数なら、キーごと(4.2 b)。読む側のキーが別なら、渡らない |
| 型の記述子、`os.Stderr`/`Stdout` | 済 | |

**選び方(手順)**: `-pass-stats` の、グローバルごとの(書き手数 × 読み手数 × 載る要素の数)の上位を出す(診断は、ADR-047 のブランチに「組成の出力」としてある。main に入れるかは、実装のときに決める)。上位のグローバルを 1 つずつ見て、**意味があるもの**だけをモデルにする。意味が分からないものは、`holds` を足さない(**数で言うだけ**。4.4)。精度のために、**型名で一括して `nothing` にしない**。

### 4.4 証拠: finding に、共有された場所の数を付ける

グローバルを通る finding に、**`shared_state`**(新しいフィールド。追加のみ。スキーマ版は上げない)を付ける:

```json
"shared_state": [{
  "place": {"kind": "global", "name": "gogs.io/gogs/internal/conf.Database"},
  "path": "/Host",
  "writers": {"flow": 1, "all": 2, "test": 0, "excluded_test": 0},
  "readers": 12,
  "first_writer": "gogs.io/gogs/internal/route.InstallPost"
}]
```

- `writers.flow`: **この finding の要素(source)を書いた関数の数**。`globalStore.writers` を、最初の 1 つの `rope` から、**要素ごとの、書いた関数の ID の集合**にする(要素は、`commitGlobals` が整列して処理するので、決定的。集合の大きさは、書き手の数の小さい数(上の測定で 1〜2))。
- `writers.all`: G に直接書く関数の数(今の `writersOf`)。
- `writers.test` / `excluded_test`: 4.1 の。
- `readers`: G を読む関数の数(`readers_`)。
- 複数のグローバルを通るときは、配列。
- `kind`: `global` か、`entry_receiver`(4.6)。

LLM の判定(`resolve`)は、finding ごとに、この欄を読む。「`flow: 1`、`all: 2`」は、読み手に近く、「`all: 100`、`flow: 40`」は、合流点の疑い。**finding の集合も、経路も変えない**(出力の追加だけ)。

### 4.5 途中で止めない

`MaxPasses`(12)は、**パスの数**で止める。連鎖の段数(`state/global-chain` の 13、30)は、1 段が 1 パスを要するので、順序に依って、パスの上限に当たる(3 言語とも、`@miss(recursion_approximation)`)。**パスの上限を、仕事量の上限に置き換える**:

- 収束するまで続ける。止める条件は、**追加された要素の総数**(`Options.Budget` の全体版: `RunBudget`)と、実時間(`-timeout`)。パスの数では止めない。
- パスの内の順序: 関数の順序(`levelsOf`)に、**グローバルの辺**(書き手 → 読み手)を足して、書き手が先、にする(循環は SCC)。連鎖が、1 パスで流れる。**finding の集合は、順序に依らない**(今も、不動点)。ただし、**代表の経路と指紋は、順序に依る**(`-workers` や、回す順で、代表の経路と、それから決まる指紋が変わる。issue #96)。順序にグローバルの辺を足すと、**finding の `path@1`(代表の経路)が動きうる**。足すのは速さのためだが、代表の経路を変えるなら、受け入れで見る(下)。
- 止まったときは、今と同じく `recursion_approximation`(全体の不確実性)と `converged: false`。

**受け入れ**: zoo の `global-chain` の `vuln13` / `vuln30` が、3 言語とも出る(`@miss(recursion_approximation)` が外れる)。Gitea と gogs の、**finding の集合と、各 finding の `path@1` が、同一**(違えば、1 件ずつ分類する: 順序だけで、別の代表の経路が選ばれたのか、本物の差か)。パスの数が減るか同じ。**または、issue #96(代表の経路が、順序に依らないようにする)を、先に直す**(直せば、`path@1` の同一を、そのまま受け入れにできる)。

### 4.6 入口どうしの受け手の状態を、同じ運び方に乗せる

「共有される場所」を、**鍵で言う**: `place = (class, field path)` か、`(global value, path)`。`globalStore` の鍵を、`*sg.Value`(グローバル)から、`Place` に一般化する。

- **グローバル**: 今のとおり。
- **入口の受け手**: **入口**のメソッドの、**受け手のパラメータ(`Param 0`)の下**への書き込み(`Param(0, "/field")` の出力)は、`Place{class: 受け手の型, path: "/field"}` に公開する。同じクラスの**別の入口**が、受け手の `/field` を読むとき、その Place から要素を読む(読み手として登録)。
- **入口の定義**: 「呼び元のない関数」ではない(呼び元が見えないだけの関数を、入口にしない)。**入口 = フレームワークが呼ぶと分かっているメソッド + 呼び元のないメソッド**。前者は、(i) `overrides` が、フレームワークの型のメソッドを実装しているもの、(ii) `kind: param` の source の関数(ルールが、「この関数は、フレームワークが引数を渡して呼ぶ」と言っているもの)、(iii) 値として登録された関数(ルーターへの登録など。ルールの `kind: param` と、登録の呼び出しから分かるもの)。
- **前提(名前を付けて、不確実性として出す)**: 「同じクラスの入口は、同じ受け手のインスタンスを共有する」(`Arc<AppState>`、DI のシングルトン、Go のハンドラ構造体)。これは**前提**で、真でないこともある(リクエストごとに作る受け手)。`shared_state.assumption: "one_receiver_per_class"` を、finding に出すだけでなく、**不確実性として出す**(新しい種別。名前は実装で決める。案: `assumed_shared_receiver`)。この Place を通った finding は、**確信度が `no_uncertainty_on_path` にならない**。
- **範囲**: 呼び元が見える関数(入口でないもの)の受け手は、呼び元が束縛するので、対象外。入口が 1 つのクラスは、対象外(公開する相手がいない)。受け手の型が不明(trait object、ジェネリック)は、公開しない(**痕跡**: `stats` に件数)。**Dart は、入口の整備(`overrides` と、登録された関数を、入口として数えること)のあとで**。

**効果**: Rust の `state/receiver-field-across-entries`(`Arc<AppState>` の `Mutex` のフィールド)が出る。おとり(別のフィールド)は、フィールドのパスで分かれるので静か(4.2 a が前提)。

## 決定

1. **「正の証拠だけ」(起点から届かない関数は、外さない)**: **はい**。ただし、第 2 段(「呼び元が、読んだ範囲で、すべてテスト」)は、正の証拠でない(フレームワークやリフレクションから呼ばれうる)ので、**シグネチャの証拠**(テストの枠組みの型を、引数か受け手に取る関数と、そこからしか参照されない関数。テストでないコードから参照されていたら外さない)に置き換えた(4.1)。`-tests` なしでも効く。
2. **入口の受け手の前提(「同じクラスの入口は、同じ受け手を共有する」)**: **はい**。ただし、`assumption` の欄だけでなく、**不確実性として出す**(確信度が `no_uncertainty_on_path` にならない)。**入口の定義**は、「呼び元のない関数」でなく、「フレームワークが呼ぶと分かっているメソッド(`overrides`、`kind: param` の source の関数、値として登録された関数)+ 呼び元のないメソッド」(4.6)。
3. **`shared_state` の追加(出力の追加のみ。スキーマ版は上げない)**: **はい**。
4. **パスの上限を、仕事量の上限に置き換える(4.5)**: **はい**。条件つき: finding の集合は順序に依らないが、**代表の経路(`path@1`)は依る**(issue #96)。受け入れは「finding と `path@1` が同一。違えば、分類」か、#96 を先に直す。
5. **定数のキーは、マップだけ**(スライス / List / Vec は入れない。添字がずれる)。`cont/slice` のおとりは、痕跡つきの過大近似として受け入れる(4.2 b)。

## 確かめていないこと

- Rust の `Mutex<Struct>` の FP の原因(`lock()` の結果の別名か、中身の 1 つの場所か)。
- 4.2 a で、`widen` と `absorbWhole` が、`Rel` を持つ要素に、どう効くか。
- `-tests` なしの gogs で、+45 が、4.2 a だけで消えるか(go-scale の `selfcopy` は再現しなかった)。
- 4.1 の第 2 段(シグネチャの証拠)が、gogs の `SetMockPicture` 以外の、テストの枠組みの型を取る関数を、いくつ外すか(外したものが、本番から呼ばれていないか)。
- 要素ごとの書き手の集合の、メモリ(今の測定では、書き手の数は最大 2。Gitea では、測っていない)。
